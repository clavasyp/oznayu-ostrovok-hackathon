# V9 — среда, климат и море: входы и смысл вычислений

[факт] `scripts/environment.py` вычисляет B01–B05, C01–C04 и E01–E04 по общей выборке. Импорт не выполняет сетевых запросов или записи. `fetch --city sochi` собирает только выбранные месяцы ERA5, `marine --city sochi` выбирает морские ячейки по выбранным OSM-пляжам, `compute --city sochi` читает снимки и записывает факты. `test` проверяет границы суточных порогов, полноту лет и координатный контракт моря. Python и геобиблиотеки — из существующего V4 venv; для одноразового чтения metadata NetCDF установлен h5py3.16 только в `environment/runtime/`, старый venv не менялся.

## Что посчитано

[факт] C01–C03: Open-Meteo Historical Weather API, явно `models=era5`, 0.25°, без `best_match` и без статистического downscaling (`elevation=nan`). Только июль и ноябрь, по30 полных месяцев1991–2020. C01 — среднее суточных средних, затем среднее30 годовых значений; C02 — среднее по годам число дней с осадками≥1мм/сутки; C03 — число дней Tmax>30°C. Сохраняются межгодовое стандартное отклонение, минимум/максимум, все30 годовых значений и число валидных дней. Любой пропуск в одном месяце отклоняет30летний результат. Дождливые дни не превращаются в вероятность дождя на даты поездки.

[факт] Суточные границы заданы фиксированным нынешним стандартным местным сдвигом (`Etc/GMT-3` для Сочи; UTC+2 для Калининграда, UTC+4 для Дубая). Это осознанный контракт, исторические переходы DST не воспроизводятся. В API этот сдвиг фиксируется на весь ответ. Для станционного сравнения возможна разница определения климатических суток. Все месяцы привязаны к явной ячейке, расстоянию до неё и её модельной высоте. Грубая горная ячейка может сильно отличаться от прибрежной станции; это не погода в конкретном номере.

[факт] E03: WorldCover2021v200 из уже скачанных V4 COG. Каждый расчёт заново на фактической координате отеля V9: пересечение растровых пикселей с кругом300м в локальной AEQD, площадь взвешивается по фактическому пересечению. Числитель — растительность классов10/20/30/40/90/95/100; знаменатель — классифицированная суша, постоянная вода80 и nodata0 исключены. Отдельно сохранены площадь суши/воды/пропусков, диагностическая доля от всей площади круга, покрытие входных пикселей. Порог валидной площади≥99%. Круг аппроксимирован256отрезками. Это исторический покров2021, не текущая зелень, парк, доступность или тень. Старый V4 делил на все валидные пиксели, включая воду: его доля не является численным эталоном новой величины на суше.

## B02: почему имя SST здесь проверено, а не угадано

[факт] Канонический B02 требует модельную потенциальную температуру на явной верхней глубине. Одного имени `sea_surface_temperature` недостаточно. Проверены публичные исходники Open-Meteo, закреплённые SHA дерева в `marine_semantic_audit.json`: API `models=meteofrance_currents` подключает MFSST; MFSST читает NetCDF `thetao` по индексу глубины0 и отдаёт под именем `sea_surface_temperature`. В соответствующем исходном NetCDF GLOBAL_ANALYSISFORECAST_PHY_001_024 прочитаны только metadata и координаты: CF `sea_water_potential_temperature`, depth[0]=0.49402499198913574м, positive=down. Полный объект865485053Б не скачивался; получено213245Б HTTPRange с учётом повторного64КБ заголовка (сам reader147709Б), массив thetao не читался. Эти сведения — контроль смысла. Основные температурные значения получены исключительно из Open-Meteo поD22.

[факт] Для июля2022 API вернул744null; выбран общий полный короткий период2023–2025, июль/ноябрь. Среднее считается по исходным6часовым шагам00/06/12/18UTC, а не по24 интерполированным часовым значениям как независимым измерениям. Все годы должны иметь полный месяц. Это `estimate`D18: три года архива эксплуатационной модели, не климатическая норма, не измерение у уреза воды и не прогноз2026/2027. Версия конкретного развёртывания API не раскрыта, публичный код не доказывает точный commit сервера; изменения upstream также остаются ограничением.

[факт] Дополнительная пространственная проверка обнаружила: публичный импортер задаёт API-координатам сдвиг+половины ячейки относительно nativeCF осей. В паспорте сохранены обе координаты и оба расстояния до пляжа; nativeCF индексы декодированы и проверены по прочитанным координатам NetCDF. Все11 морских nativeCF точек Сочи дополнительно попали в класс80 «постоянная вода» WorldCover2021. Морская маска самого Open-Meteo строится из не-fill значений thetao; API запрашивается с `cell_selection=sea`. Возможная сухопутная позиция отображаемого центра не объявляется береговым измерением. Указанный OSM-пляж не означает проверенный публичный вход.

## Почему остальное неизвестно

[факт] B03/C04/E01 на обе даты поездки находятся вне горизонта прогнозов; исторические ряды/прошлые прогнозы не заменяют будущий прогноз. B01 требует датированный материал именно выбранного участка, B04 — актуальный флаг/статус уполномоченной службы с beach_id, B05 — сопоставленный лабораторный протокол; маркетинговые тексты или общегородские новости не проходят эти контракты. E02 — станционное измерение, тогда как Open-Meteo поD22 возвращает модель CAMS; прямые станции/OpenAQ требуют отдельного решения о допустимости и прав конкретного провайдера. E04 требует corrected BlackMarbleA3+QA или достаточный correctedA2 ряд; отсутствие такого входа не заменяется другим VIIRS/JPEG.

[факт] У исторических фактов `observed_at=null`, когда известен только год композита/интервал, они явно указаны в параметрах; точная дата загрузки находится в provenance. `valid_to=null`: TTL — не обещание физической неизменности. Срок перепроверки вынесен в `refresh_after`.

## Проверка и цена

[факт] Точные результаты, хеши, размеры и времена последнего прогона — `results/environment/<city>_summary.json`; время сетевого сбора и локального расчёта разделено. Сырые JSON+meta имеют URL/параметры/время/HTTP/hash, общий журнал `http_ledger.jsonl`. Публичный API допустим по решению пользователяD22 для некоммерческого хакатона; коммерческая эксплуатация Historical требует Professional либо собственного сервера. Сумма консервативных весов запросов записана отдельно; это оценка нагрузки, не счёт провайдера. Запросы ограничены420консервативными вызовами/минуту, ниже опубликованного600.

[факт] `qa/environment/audit_cases.csv` — восемь случаев «разметка Codex», пригодность эталона явно отмечена. Четыре сравнения C01 со станцией37099 NOAA/WMO1991–2020 описывают пространственную репрезентативность, а не чистую ошибку калькулятора. Два B02 проверяют смысл, глубину и морскую ячейку, но не независимую точность температуры; два E03 показывают отсутствие независимой датированной разметки300м. Все восемь `gold_eligible=false`. Precision/recall и MAE по независимому эталону не измерены. Тесты реализации и сверка API не переименовываются в эмпирическую точность.

[вывод] Пакеты города нужно собирать заранее с нормализованным реестром источников; повторяющиеся30ссылок в каждой климатической строке JSONL предназначены для автономного аудита и в Postgres должны раскладываться в `source/fact_source`, что соответствует core.md. При старте у жюри сетевой сбор не нужен: нужны проверка хешей и загрузка готовых фактов. Точное время полной Docker-сборки этим исследованием не измерялось. Расценки на дополнительную разметку, измерения и спутниковые входы не получены, денежную сумму не выдумываем.

## Уточнение v9.2: морской контекст независимо от маршрута

[факт] Принятый root-протокол применяется ко всем8городам. Если есть выбранный морской пляж пешего расчёта, он сохраняется. Если нет — из подтверждённых по OSM-coastline полигонов выбирается ближайший к координате отеля, с тем же фильтром явных access=no/private/customers и сохранённым расстоянием выбора. Отдельный вход `--marine-targets` явно указывает `*_marine_targets_with_fallback.jsonl`; путь и SHA фиксируются в mapping. `selection_method=nearest_marine_polygon_fallback` не утверждает ни публичный вход, ни пляж отеля, ни подходящий отдых гостя. W01 и его маршруты не изменяются. Отсутствие пути не доказывает отсутствие физически вычислимого морского контекста.

[факт] Историческая версия Сочи v9.1 сохранена в `checkpoints/sochi_v9_1_environment/` с SHAmanifest. В v9.2 B02 стал89/89estimate вместо86/89; поменялись ровно3отеля×2месяца, прежние численные значения неизменны. Для TravelInn выбран лишь referencepolygon «Нудистский пляж Кудепста» в34.35км по прямой; это не заявление «море рядом» или пригодности пляжа. `qa/environment/sochi_v9_2_delta.json` хранит численную дельту и выбор. Восьми audit-case сохранены currentfact_id и прежние ID со ссылкой на исторический снимок; статусы gold не повышались.

[факт] В данном запуске профиля моря B01–B05 у Москвы/Казани/Минска имеют not_applicable при параметре marinebeach. B01/B04/B05 в общем каталоге могут использовать речной/озёрный пляж — другой выбор параметров; отсутствие моря не означает отсутствие любых пляжей.

[факт] Финальная сетевая сводка разделяет реальные HTTP-запросы кERA5/Marine, успешные ответы/ошибки/семантически пустые пробы, декодированные размеры ответов и оценку weightedquota. Проверки `qa/environment/build_all8_qa.py` не делают HTTP; независимый арифметический способ сверяет вычисления с теми же APIмассивами, поэтому не является независимым физическим эталоном.


[факт] Для опережающего прогрева допускается `marine --cache-only --marine-targets <explicit file>`: сохраняются API-снимки и отдельный `marine_mapping_<city>_provisional.json`. Калькулятор читает только финальный mapping, связанный с SHA окончательного файла целей. В этом запуске СПб/Калининград/Стамбул получили final вовремя, поэтому предварительные hotel facts не создавались. Выбор морских полигонов дополнительно проверяет `marine_classification.accepted=true`; дубли ответов кеша не считаются несколькими годами.


[факт] Финальный пространственный QA дополнительно отвергает finite model-wet точки, если декодированный native CF центр попадает на известную сушу WorldCover2021. Для того же морского полигона перебираются нативные центры с class80 в пределах30км, проверяются конечные Open-Meteo ответы и выбирается ближайшая фактически возвращённая finite/class80 точка. Классы0/нет покрытия отдельно означают отсутствие независимого растрового подтверждения, а не доказанную сушу. В конечных данных таких неподтверждённых случаев нет: все578 B02контекстов имеют class80.

[факт] Этот QA отклонил11 первоначальных привязок:1пляж Стамбула (19отелей) и10пляжей Дубая (23отеля). Финальные точки находятся в воде поWorldCover2021; для Rumeli Kavağı Plajı выбран центр41.25/29.083333969 в7.289км от того же пляжа. Отдельный `qa/environment/coastal_wetcell_validation.json` хранит исходные/заменяющие точки, причины, пробы и пределы. Это пространственная проверка модели, не независимое измерение температуры или актуальная батиметрия.

[факт] Итог8городов:439отелей,7,313строк параметризованных фактов. E03/C01/C02/C03 полностью computed у439; B02 estimate у289отелей пяти морских городов, по2месяца, и not_applicable у150внутренних в выбранном marineпрофиле.
