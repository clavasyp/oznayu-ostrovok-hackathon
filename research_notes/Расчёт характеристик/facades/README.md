# V9: фасады, солнечная геометрия и история зданий

[факт] На выборке Сочи из 89 объектов `facades.py` связал 58 объектов с 68 контурами зданий. Ближайший контур без совпадения полного адреса не принимается. Точный адрес из сохранённого `facts.register.address` имеет приоритет над укороченным адресом карточки. Корпус, дробь и литера не отбрасываются. Для Radisson дополнительно совпали телефон, адрес и полигон территории OSM. Это исследовательские связи; перепись всех корпусов и размещение категорий по ним не подтверждены.

[факт] Основной результат — 1068 фактов, по 12 характеристикам для каждого объекта. H03 получен из `building:levels` у 44/89 объектов с одним однозначно сопоставленным контуром. Ещё есть 58 отдельных записей H03 для индивидуальных контуров: они включают записи этих 44 объектов и не прибавляются к ним повторно. V01–V06, S01–S03, H01 и H02 пока `unknown` во всех 89 случаях. Ни один неизвестный не заменён отрицательным значением.

[факт] Построен веер из 4363 ячеек «контур × сегмент фасада × надземный ординальный этаж». Если число этажей отсутствует, создаётся одна ячейка с неизвестным этажом. Для каждой ячейки сохранены 25 полных паспортов: пять непараметрических признаков V, V05/S01/S02 для шести дат проживания и S03 для двух месяцев. Всего 109075 паспортов, 5403653 байта gzip. Текстовый геометрический веер — около 32 МБ. Даты выезда 17 ноября и 18 июля не входят в ночи проживания; это явный параметр, который можно поменять.

[факт] В расширенном снимке OSM — 140845 контуров, у 46992 есть целочисленный `building:levels`, у 668 — числовой `height`. Собственная этажность не доказывает высоты соседей, деревьев и козырьков. `height` не считается измеренным обследованием. GLO-30 не использован как DTM; 3D-GloBFP не прошёл фильтр условных прав. Физические окна, абсолютная высота взгляда и общий вертикальный datum не подтверждены. Поэтому веер не выдаёт видимость или часы прямого солнца как факты о существующем окне.

[факт] Рассчитаны отдельные компоненты: нормаль каждого сегмента, лучи до картографированных контуров, интервалы возможного первого препятствия при явно условной плоской земле, кандидаты общих стен и геометрические верхние границы солнечной экспозиции. Для солнечных положений применён NREL SPA (`pvlib 0.16.1`, BSD-3-Clause), IANA-зона `Europe/Moscow`, сетка 5 минут. У границ интегрирования сохранена погрешность сетки. Эти компоненты не названы S01/S02 или V05. Деревья, тени и отсутствие окна не игнорируются. Для V02–V04 сохранены реальные OSM-кандидаты вершины, памятника и парка с ID/версией, расстоянием и азимутом; наличие цели также не означает её видимость.

[факт] `qa/facades/test_scenes.py` проверяет интервальный LOS: известная высокая стена закрывает луч, низкая пропускает, неизвестная высота даёт неизвестность, более высокий этаж меняет результат, точка внутри другого препятствия не считается прозрачной. Проверяются наружные нормали, недопустимые дробные этажи и отсутствие выдуманной высоты. Независимый код Astral сверяет шесть астрономических положений с SPA, допуск 0,1°. Всего 26 проверок. Это проверки алгоритма и согласия реализаций, не точность реальных окон.

[факт] Для сверки с Островком есть 16 записей: 9 по году, 3 по этажности и 4 по заявлениям вида из названий категорий. В Radisson карточка сообщает 8 этажей, а четыре сопоставленных контура OSM содержат 9/8/8/7. Это разные области и, возможно, система счёта; победитель не назначен. У «Коралла» `yearBuilt=1967`, у точного контура 219/28 `start_date=1973`: событие завершения строительства не доказано, разница лет сохранена как кандидат для проверки, не установленная ошибка. В «Магнат-Дубай» исходные числа 4 и 4 совпадают, но система счёта Островка не определена.

[факт] Восемь независимых первичных случаев для разметки — `reference_cases.csv`: официальные страницы/снимки «Коралла», LAVICON Fregat, «Аквамарина», Radisson и Marina Yacht. У каждого указана причина, почему он пока не эталон полного канонического контракта: обрезанная фотография, неизвестный этаж/сектор/дата или неуказанная система счёта. Например, [оператор «Коралла»](https://adlerkurortsochi.ru/korpusa/) сообщает 15 этажей; это независимое от Островка числовое согласие с OSM, а не обследованный надземный счёт. Заявление [Radisson о категории](https://www.radissonhotels.com/en-us/hotels/radisson-collection-resort-sochi-spa/rooms) не является калиброванным фото конкретного окна. Поэтому precision/recall для V/S/H по этой ветке не измерены. Фотографии сохранены для частного аудита; разрешение на их публичное тиражирование не установлено.

[факт] Финальный прогон Сочи: 29,38 секунды, включая 5,86 секунды чтения сцены и 1,47 секунды сопоставления. Остальное — общая обработка V/S/H, сериализация и gzip; независимые времена каждого семейства не выделялись. Время сборки Docker и стоимость полевого обследования не измерены. Новых запросов к Островку — 0.

[вывод] Для реального положительного вывода о виде и солнце нужны привязанные окна/категории, вертикальный разрез, независимое подтверждение препятствий и покрытие рельефа. Вопрос отельеру должен запрашивать эти конкретные недостающие поля. Средний этаж или приблизительная высота здания их не заменяют.

## Воспроизведение

Из корня проекта:

```sh
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/scripts/facades.py' --city sochi
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/qa/facades/test_scenes.py'
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/qa/facades/check_outputs.py' sochi
```

Код не делает сетевых запросов, не меняет входные снимки, не выполняет работу при импорте. Входы: общий `cohort/hotels.jsonl`, расширенный Sochi PBF-срез или прежний городской OSM JSONL, сохранённые снимки Островка, `facades/external_match_evidence.json`. Выходы — только `results/facades/`. Для других семи городов меняется `--city`, после разрешения корневого координатора начать этот этап. Лицензированные библиотеки установлены отдельно в новом `vendor/`, существующий V4 runtime не менялся.
