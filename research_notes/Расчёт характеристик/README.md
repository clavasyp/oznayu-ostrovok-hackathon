# V9 — воспроизводимый расчёт каталога

Рабочая папка V9. Старые исследования используются как входы и не переписываются. Когорта — 439 реальных объектов: Большой Сочи 89 и семь городов по 50. Дагомыса в доступном OTA-кеше нет; новые запросы к Островку запрещены заданием. 34 дополнительных объекта Сочи происходят из сохранённой городской выдачи и не имеют снимка категорий.

## Входы и выходы

- `source_snapshots/` — задание, решения, каталог и прежняя память на начало V9; SHA256 в manifest.
- `cohort/hotels.jsonl` — actual masterId, координаты, источник и JSON pointer каждого объекта; не ID из URL.
- `scripts/common.py` — общий протокол и две поездки, локальная суббота 02:00.
- `scripts/facades.py` — точное сопоставление адресов, контуры, надземные ординалы, фасады, сценарная геометрия LOS и солнца; V/S нельзя превратить в факт фактического окна без недостающих входов.
- `scripts/geo.py` — 29 признаков: расстояния, граф пеших маршрутов, часы, известные лестницы/освещение и явные отказы. Морской пляж проверяется отдельно от любого `natural=beach`; запреты на узлах и рёбрах соблюдаются.
- `scripts/environment.py` — 13 признаков B/C/E: исторические месяцы ERA5, площадь растительного наземного покрова, короткий морской ряд с явной глубиной; будущий прогноз не заменяется нормой.
- `results/` — полные JSONL паспорта, маршруты, веер фасадов и этажей, измеренное время и размер.
- `integrated/` — интеграция, матрицы покрытия и структурная QA. Одинаковые записи H03 в двух логических экспортных представлениях удаляются по полной идентичности; разные значения одного fact_id вызывают ошибку.
- `hotelier/` — 26 вопросов и исходные заявления V7 плюс типизированные поля сохранённых категорий V5 как предзаполнение. Ответы не отправлялись, не имитировались и не выдаются за подтверждение.
- `validation/` — разметка Codex, независимые первичные источники, станционные сравнения и отдельная арифметическая проверка. Количество строк аудита не является размером эталонной выборки. Человеческая перепроверка ожидается.
- `qa/` — синтетические сцены, проверки паспортов, независимая рецензия и сохранённые ошибочные результаты до исправлений.

## Повтор расчёта

Запуск из корня проекта. Для текущей машины используется существующий Python V4; новые пакеты установлены только в каталогах V9. Фактические версии сохранены в `runtime_versions.json` и `requirements-v9.lock.txt`; для другой машины нужен отдельный Python 3.13 environment с этими зависимостями и доступом к указанным в manifest входам.

Первичный промежуточный прогон Сочи выполнялся такими командами; ниже описаны последующие исправления, необходимые для текущего результата.

```sh
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/scripts/facades.py' --city sochi
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/scripts/geo.py' --city sochi
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/scripts/environment.py' compute --city sochi
python3 'research_notes/Расчёт характеристик/scripts/integrate.py' --cities sochi
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/scripts/numerical_audit.py'
python3 'research_notes/Расчёт характеристик/scripts/station_comparison.py'
python3 'research_notes/Расчёт характеристик/scripts/assemble_validation.py'
```

`facades`, `geo`, `compute` и интеграция работают без сети. Для новой версии целей пляжа `compute` откажется использовать морскую привязку с несовпадающим SHA. Отдельные действия `environment.py fetch` и `marine` обращаются к Open-Meteo и должны выполняться заранее, в пределах согласованных D22 условий и квоты. `validation_sources.py` загружает только явный перечень первичных страниц для аудита; он не является сборщиком гостиничного каталога. По умолчанию повтор сети не нужен: исходные ответы сохранены.

Сначала формируется и проверяется промежуточный отчёт Сочи. Семь остальных городов запускаются теми же калькуляторами после этой контрольной точки. `spb` сопоставляется со старым ключом V4 `saint_petersburg`; Батуми в текущие восемь городов не включён.

Для семи городов географический запуск выполняется через **`scripts/run_geo_v9_other_city_compact.py`**, после готовности `building_matches` соответствующего города. Он добавляет узлы запретов, которые не выбирал старый фильтр V4, из **того же сохранённого PBF**, сохраняет составной manifest и точные геометрии выбранных POI-маршрутов. Прямой запуск исходного `geo.py` на этих городах не воспроизводит дополненные входы; ранний `run_geo_v9_other_city.py` сохранён как история неудачных попыток, а не рекомендуемый запуск. Пример подготовки и расчёта Москвы:

```sh
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/cohort/extract_v9_node_restrictions.py' --city moscow
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/scripts/run_geo_v9_other_city_compact.py' --city moscow
```

Runner проверяет SHA принятого `geo.py` и сохраняет версии фактически применённых адаптеров. Компактные контейнеры графа прошли 19 точных проверок эквивалентности весов, порядка, ID, геометрии и атрибутов; это не полевая точность. Циклический GC отключён на время одного городского процесса, подсчёт ссылок работает, память освобождается при выходе. Неограниченный поиск `OpeningHours.next_change()` заменён явным `null` с причиной: характеристике нужна проверка состояния в заданный момент. `is_open` / `is_closed`, часовой пояс и применимый календарь сохраняются; проверка holiday-выражений не может быть подменена отсутствующим календарём. На ноутбуке с 8 ГБ тяжёлые процессы фасадов и графа чередуются. Остановленные попытки и уточнения их диагноза учитываются отдельно от успешного времени; сумма внутренних групп не заменяет полное время runner.

Для Дубая фактический финальный запуск использует `scripts/run_geo_v9_other_city_compact_v2.py --city dubai`: версия AE2 допускает выражения без PH/SH при неподдерживаемом коде страны AE, сохраняя Asia/Dubai. Выражения с праздниками без применимого календаря остаются неизвестными. Первый compact runner сохранён как фактическая версия остальных шести городов.

Текущий Сочи дополнен двадцатью узлами доступа из того же сохранённого PBF. Исправление F01 и полная повторная выборка всех кандидатов описаны в `qa/geo/sochi_F01_node_repair_report.json` и `qa/geo/sochi_full_corrected_reselect_audit.json`. `qa/geo/reselect_sochi_corrected_readonly.py` воспроизводит полный исправленный расчёт в отдельном каталоге QA, не публикуя его поверх принятых файлов. Один прямой запуск исторического `geo.py --city sochi` эту дополнительную фазу не воспроизводит.

Версия `v9.2.facades` проверяет полный номер дома с буквой и корпусом; названия городов и номер квартиры не считаются корпусом. После аудита всех восьми городов исправлены пять наборов привязок: Сочи, Москва, Петербург, Казань, Калининград. Итоговые адреса, 17 регрессионных случаев, архив 60 прежних файлов и хеши находятся в `qa/facades/final8_review.json`. Целевой пересчёт N02/N03 использует полный diff прежних и новых привязок, не строит граф заново и не меняет остальные факты. Версии исполненных скриптов, `repair_seconds` и архивы записаны в `results/geo/*_run.json`; итоговая проверка субъектов — `qa/geo/all8_building_axis_join_coverage.json`. Повторная публикация ремонтных фаз защищена контрольными точками; для обычного чтения результата запускать её снова не требуется.

После готовности всех восьми городов:

```sh
python3 'research_notes/Расчёт характеристик/scripts/integrate.py' --cities sochi moscow spb kazan kaliningrad minsk istanbul dubai
python3 'research_notes/Расчёт характеристик/scripts/audit_fans_all8.py'
python3 'research_notes/Расчёт характеристик/scripts/scale_metrics.py'
'research_notes/Аудит данных 8 городов/.venv/bin/python' 'research_notes/Расчёт характеристик/scripts/numerical_all8.py'
```

`scale/city_metrics.csv` отделяет расчёт, сбор климатических/морских ответов, размер фактов и общий размер файлов результата. Исправление F01, его публикация и повторная контрольная выборка имеют отдельные столбцы; `geo_building_join_repair_s` учитывает целевые пересчёты N02/N03 и не прибавляется к историческому времени полного геопроцесса. `scale/family_metrics.csv` сохраняет измеренные совместные группы: время W/A/Q или V/S/H нельзя повторно суммировать по семействам. Байты логических JSONL-строк и размер физических файлов имеют разные знаменатели.

## Что именно считает покрытие

В матрице одна пара отель×характеристика учитывается один раз по лучшему фактически полученному статусу **хотя бы для одного явно указанного субъекта и набора параметров**. Это не обещание для всего отеля, всех корпусов, номеров или дат. Отдельно сохранён счётчик, где разрешены все выданные строки; суммы по строкам фактов и по парам имеют разные знаменатели. 54 признака выделяются из канонического JSON по первому рецепту А/Б, остальные 26 — по В. Валидное `false` не запускает следующий рецепт.

Сценарная геометрия фасада не доказывает наличие окна в выбранной точке. OSM `building:levels` описывает надземный счёт источника, а не гарантированный этаж категории. DSM не является DTM; W04 имеет отдельный исследовательский рецепт `W04-D18-DSM`, все канонические DTM-рецепты при этом остаются отклонёнными. Оценки исключены из обязательных условий. Ноль известных лестниц и ноль учтённых заведений не означают отсутствие всех физических лестниц или заведений. 100% неизвестного освещения не означает темноту.

Исторический WorldCover 2021 и климатическая норма не становятся наблюдениями 2026 года после нового расчёта. `valid_to` описывает реальную валидность, а срок перепроверки хранится отдельно. Неназванные или не измеренные даты остаются `null`. Данные OSM требуют атрибуции и соблюдения ODbL; данные WorldCover/Open-Meteo — атрибуции CC BY 4.0. Бесплатный сервис Open-Meteo использован для согласованного некоммерческого хакатона; производственный доступ определяется D22. Условные права GloBFP не выданы за разрешение на промышленное использование.

## Перенос в ядро

Это вычислительные исследовательские модули, ещё не приложение FastAPI/PostGIS/Dagster. Для импорта в core §2.2 нужны технические адаптеры: строковый `city_id` и внешние `subject_id` в справочники БД, `algorithm_version` → `algo_version`, `calculated_at` → `computed_at`, `confidence.level` / `confidence.reason` → отдельные поля `confidence` / `confidence_reason`, `observed_at` в известный интервал наблюдения, JSON-источники/зависимости в таблицы. Составной субъект `facade_physical_floor` требует явной пары фасада и физического этажа; его строку нельзя непосредственно записать в bigint. Полный текст отказа сохраняется вместе с нормализованным кодом причины; неизвестная уверенность не превращается в калиброванную вероятность. Неизвестные и отказанные рецепты должны сохраняться при импорте. Привязку категории к корпусам, сторонам и физическим этажам предоставляет отельер.

Геопакеты строятся заранее. Запуск жюри должен читать подготовленные данные и поднимать API на 8080 с `/health`; скачивание исходных 19 ГБ и внешние API в этот запуск не входят. Собственно `docker compose up --build ≤10 минут` здесь не измерялся: приложения и его контейнера задание V9 не создавало. Часы работы, разрешения пляжей, расписания и события перед реальной поездкой требуют обновления из соответствующих источников.
