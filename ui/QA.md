## 27 октября 2026 — правки по ревью PR №23

API в режиме `fixtures` (Сочи — 11 отелей, Москва — 10), без ключа LLM: разбор правилами. Production-сборка и dev-сборка React (предупреждений в консоли нет). Ширина экрана — компьютер, 414 и 360 px.

**Разбор запроса**
- «Закат и море»: уточнения «тихий» и «даты поездки» показаны оба.
  - «и то и другое» → запрос «тихий (в номере) номер… Снаружи тоже тихо.»: тишина в номере, дороги и бары, уточнение снято.
  - «Выбрать даты поездки» → «Применить даты» → в запросе «…, 10–13 ноября 2026», у заката дата 10 ноября, уточнение о датах снято.
- «Поздний заезд»: «ИЛИ» — один чип, перенести его нельзя (подсказка). «Открытая аптека» перенесена в «желательно», по «Готово» подборка пересчитана, пункт «не разобрали связь» не появился. Повторный поиск правку сохранил, «Сбросить правки» вернул как было.
- «Посмотреть город»: «доехать до Большого театра» — в «обязательно» с пометкой «не проверяем», ресторан — в «желательно» с местом и радиусом.
- «Для удалённой работы»: «с быстрым Wi-Fi» — в блоке «Не учли в поиске». «Без ступеней»: «маршрут до пляжа», «доступный вход» — там же.

**Выдача и карточка**
- Подписи — словами гостя и названиями из API. Повтор («тихий» — дороги и бары) — с названием характеристики. Сырых кодов нет.
- Значки по вердикту: ✓, ✗, ?. Сначала обязательные условия, потом желательные, с пометкой.
- Пометки «оценка» (пешком до пляжа, температура моря) и «ответ имитатора отельера» (после ответа из песочницы).
- Под статусом — объяснение. В «Подробнее» оно первым абзацем, условия — по двум группам.
- «Откуда знаем» — без JSON. У ответа отеля — цитата, вопрос, время и «Песочница · ответ имитатора».
- Постраничная выдача с `total` / `counts` — проверена подменой ответа в браузере, по 4 на страницу:
  - «Показать ещё» догружает с `offset` и с тем же AST;
  - фильтр «Уточнить» просит страницу с начала своего статуса;
  - число найденных и фильтры — по `counts`.

**Поездка и оформление**
- «Море в июле» → оформление: «Посчитано для июля, а поездка — 10–13 ноября 2026», без «выполнено».
- Смена дат в оформлении на 10–14 июля → в запросе «…, 10–14 июля 2027», подборка и условия пересчитаны: «Похоже, подходит — это оценка».
- Кнопка — «Забронировать (имитация)», пометка об имитации — на обоих шагах.

**Кабинет отельера**
- Отели — города гостя, поиск по названию.
- «Ответ имитатора» (можно с животным, лифт): показано, что понял агент — поля с цитатами — и уточняющий вопрос; статус отеля «до → после».
- «Верно» (детская кроватка) — подтверждение цитат со страницы Островка. «Верно» без сведений со страницы недоступно.
- «Не знаю» — без прошлого текста; статус «Отель не знает».

**Панель команды**
- Свой город панели.
- Журнал «что спрашивают, а мы не знаем» — из `GET /api/out-of-catalog`.
- Черновик характеристики — `POST /api/specs/draft`: YAML, предупреждения. Пробный расчёт — `POST /api/specs/trial`: честное «калькулятор ещё не зарегистрирован».

**Мобильный экран**
- 360 и 414 px: прокрутки вбок нет ни у гостя, ни в кабинете, ни в панели, ни в карточке и оформлении.

## Автоматические проверки

`npm test`:
- правка разбора: перенос по `atom_id`, граф `logic`, веса;
- подписи, значки и пометки статусов;
- постраничная выдача и фильтр, ответы на уточнения;
- даты в тексте запроса, поездка из разбора, расхождение месяца, «сегодня» по поясу города;
- факты словами и факты окон одной строкой, подтверждение «Верно», что понял агент;
- календарь, гости, группы маркеров.

`npm run build` — production-сборка React / Vite.

## Что ещё зависит от API

- `limit` / `offset`, `total` и `counts` в `POST /api/search` — без них интерфейс получает всю выдачу и показывает её частями.
- Сводка окон (`windows`) у вида и заката — в `explanation.text`; без неё — только причина.
- Режим базы и ключ LLM в этой проверке не запускались. Наличие, тариф и бронирование не запрашиваются — оформление остаётся имитацией.
