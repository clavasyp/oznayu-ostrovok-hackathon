# ui/

Интерфейс: гость, отельер, команда.

Владелец: Андрей. Изменения в чужой папке — через PR владельца.

## Локальная разработка

```powershell
npm ci
npm run dev
```

Vite запускается на `http://localhost:5173` и проксирует `/api/*` в FastAPI на `http://127.0.0.1:8080`.
Для production интерфейс собирается в `dist/`:

```powershell
npm run build
```

Полный запуск из корня репозитория: `docker compose up --build -d`. После миграций и загрузки пакетов интерфейс и API доступны на `http://localhost:8080`. Vite на 5173 использует тот же API.

В Docker API работает с базой: восемь городов, факты v9, категории номеров и размещения. Карточки показывают источники и причины неизвестности, панель команды — покрытие, оба вида противоречий, журнал «что спрашивают, а мы не знаем» и черновик новой характеристики.

## Что делает интерфейс

**Поиск.** Текст запроса разбирает агент-поисковик на сервере: без ключа LLM — правилами, с ключом — моделью (`POST /api/search`). Подписи условий — из API: у пунктов `label` (слова гостя) и `feature_name` (название характеристики), полный словарь — `GET /api/meta/labels` → `features`. Своего словаря кодов в интерфейсе нет.

**«Я понял так».**
- Обязательные и желательные условия; атомы одной группы «ИЛИ» — одним чипом, «НЕ» — с «не».
- Части вне каталога (`out_of_catalog`) — в своей группе по `requiredness`, с пометкой «не проверяем» и местом (`place`), если оно есть.
- Неразобранные куски (`unparsed_spans`) — блок «Не учли в поиске»: ни одна часть запроса не теряется молча (D34).
- Все уточнения (`clarify`). Выбор уходит в поиск через текст запроса — его снова разбирает сервер: «тихий (в номере)», «тихий (снаружи)», «…Снаружи тоже тихо». Уточнение «на какие даты» открывает выбор дат.
- «Изменить» переносит одно условие по `atom_id`. Члены «ИЛИ» и «НЕ» не переносятся (подсказка: поправить текст), атом верхнего «И» уходит из графа `logic` вместе с узлом, веса желательных в сумме дают 1, обязательное — только явное. Подборка пересчитывается по «Готово»; правка сохраняется для следующих поисков, пока в разборе есть то же условие, — «Сбросить правки» её снимает.

**Выдача.**
- Карточка: статус, `explanation.text` под ним, условия — сначала обязательные, потом желательные, с пометкой. Значок — по вердикту (✓ да, ✗ нет, ? неизвестно).
- Пометки статусов фактов: «оценка» (D18) и «ответ имитатора отельера» (D31), а также «со слов отеля», «данные Островка», «проверено командой».
- Постранично: `limit` / `offset` в запросе, «Показать ещё». Число найденных и фильтр статуса — по `total` и `counts` из ответа. Старый API без них отдаёт всё сразу — тогда интерфейс показывает выдачу частями на месте.
- Устаревшие ответы не затирают новые: поиск отменяется при следующем, карточка отеля и страницы — по номеру запроса.

**«Подробнее».** Объяснение первым абзацем: у первых результатов оно приходит с поиском, у остальных — `POST /api/explain` при открытии (кэш на поиск). Условия — по группам «обязательные» и «желательные»; у «ИЛИ» — варианты. «Откуда знаем»: значения и параметры словами (месяц, цель, радиус), служебные параметры скрыты; у ответа отеля — цитата, вопрос, время и кто ответил. Факты окон (`facade_physical_floor`, `facade`) — одной строкой на характеристику.

**Поездка и оформление.**
- Даты и гости из запроса (`ast.dates`, `ast.guests`) становятся поездкой.
- Выбранные даты уходят в поиск через текст запроса в форме, которую понимает разбор («10–13 ноября 2026»): даты в тексте заменяются, иначе дописываются. Так закат считается на дату, а температура моря — на месяц поездки.
- Условие, посчитанное на другой месяц или дату, в оформлении не «выполнено»: «Посчитано для июля, а поездка — 10–13 ноября».
- «Сегодня» — по поясу города поездки. Последний шаг — «Забронировать (имитация)» с постоянной пометкой «Имитация оформления Островка. Реальная бронь не создаётся» (D31).

**Кабинет отельера (песочница).** Город — тот же, что у гостя, можно сменить; отель — поиск по названию. Сведения со страницы Островка — `q.prefill`. Ответы:
- «Верно» — подтверждение цитат со страницы;
- «Не знаю» — `dont_know` без текста;
- «Ответ имитатора» — `POST /simulate`, затем `/answers`;
- «Отправить ответ» — свой текст.

Ответ сразу разбирает агент-отельер (правила или модель): поля с цитатами становятся фактом и пересчитывают выдачу; под ответом — что понял агент (`agent.fields` с цитатами), уточняющий вопрос (`agent.followup`) и вопрос о расхождении с расчётом (`conflict_questions`). `answered_unparsed` — только если агент не нашёл в тексте ответа на вопрос: текст сохранён без факта. Все ответы со стенда уходят с `is_simulated: true` и `respondent` «Песочница» / «Имитатор отельера» — гость видит пометку «ответ имитатора», а не «со слов отеля».

Вкладка **«Где окна номеров»** — вопрос о размещении на каждую категорию (`GET /api/hotelier/{id}/placement-questions`, D17):
- статус: ответ на этот вопрос учтён (`answer_status`) или у категории уже есть размещения из другого источника (`placement_status`);
- корпус: при нескольких корпусах — отметить в списке (адрес, этажность, стены по карте, ссылка на OpenStreetMap) и написать, как отель его называет → `building_aliases`; один корпус подставляет сервер;
- «Ответ имитатора» — `POST …/placement-simulate`: заполняет текст и отмечает корпуса, отправляет отельер;
- «Отправить» — `POST …/placement-answers` с `is_simulated: true` и `respondent` «Песочница» (D41-8). Итог: `answered` — сколько размещений, этажей и стен, полнота и гарантия, что понял агент; `needs_clarification` — уточняющий вопрос, ничего не сохранено; `real_answer_kept` — настоящий ответ остаётся; `not_placed` — корпусов нет в справочнике.
- После `answered` подборка гостя того же города пересчитывается: видно «было → стало» у отеля и статус категории; «Проверить в поиске» открывает отель в подборке.

**Панель команды.** Свой город панели (город гостя не меняется). Покрытие без неприменимых в знаменателе. «Что спрашивают, а мы не знаем» — `GET /api/out-of-catalog` (журнал пишет поиск по тексту). «Новая характеристика» — `POST /api/specs/draft`, правка YAML и `POST /api/specs/trial`; ничего не сохраняется и не включается.

## Ограничения

- Геометрии маршрутов и мест рядом API не выдаёт — слои карты «скоро».
- Очередь ручной проверки (D33) — заглушка: endpoint для curated-фактов ещё не готов.
- Наличие номеров, тариф и настоящая бронь не запрашиваются: оформление — имитация.

## Проверка интерфейса

`npm test`:
- правка разбора (перенос по `atom_id`, граф `logic`, веса);
- подписи без сырых кодов, значки по вердикту, пометки статусов;
- постраничная выдача и фильтр по `counts`, ответы на уточнения;
- даты в тексте запроса, поездка из разбора, расхождение месяца;
- факты словами, факты окон одной строкой, подтверждение «Верно»;
- календарные границы, гости, группы маркеров на карте.

`npm run build` проверяет production-сборку. Ручной прогон — в [QA.md](QA.md).

## Как интерфейс попадает в образ

Docker собирает его сам (`Dockerfile`, стадия `ui`, Node 24 LTS), если в этой папке есть `package.json`:

- `npm ci`, если рядом есть `package-lock.json` (лучше закоммитить его — тогда версии зафиксированы); иначе `npm install`;
- затем `npm run build` — результат должен лечь в `ui/dist/` (`index.html` + файлы), как у Vite по умолчанию.

FastAPI отдаёт `ui/dist` на `/`. Любой путь вне `/api` без своего файла получает `index.html`, поэтому маршруты на стороне браузера (React Router) работают и при обновлении страницы.

API — тот же адрес, относительные пути `/api/...`. Для `npm run dev` (Vite на 5173) API на 8080 уже разрешает CORS с `http://localhost:5173`. Можно вместо этого настроить в Vite `server.proxy` на `http://localhost:8080`.
