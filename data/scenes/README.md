# Сцены высот вокруг отелей показа

Задача 2б: вокруг отелей показа собраны соседние здания с этажностью и высотой. Собирает
`calculators/view_scene.py`, источник — OpenStreetMap (ODbL 1.0), **та же выгрузка v9**
(`cohort/osm_sochi_extended.jsonl`, 22.10.2026, sha256 в паспорте сцены), по которой считает вид
и солнце лид. Сети модуль не касается.

**Это справка, а не вход расчёта.** Расчёт вида и солнца (`calculators/view_sun.py`, D40) читает
выгрузку и сопоставление корпусов v9 напрямую. Сцена отвечает на вопрос «что стоит вокруг отеля
по сторонам света» и нужна, чтобы сверять окружение с картой.

## Что собрано

| Отель | Зданий в 200 м | Из них свои | С высотой | Ближайшее чужое |
|---|---|---|---|---|
| Radisson Collection Парадиз СПА (13736470) | 47 | 4 (сопоставление v9) | 33 | 63,1 м |
| LAVICON Отель Фрегат (6443737) | 78 | 1 (точка в контуре) | 35 | 45,2 м |
| Курортный Отель COOCOOROOZA (8869683) | 49 | 1 (сопоставление v9) | 14 | 61,1 м |

Новых высот сцена не даёт: этажность здесь из той же выгрузки, что у лида (в выгрузке этажность
есть у 46 600 зданий из 140 224, тег `height` — у 406; «668 из 140 845» в разборе v9 — это
метрическая высота). Здания с одним `building:levels` (×3 м) — оценка высоты, а не замер.

**Что нужнее сцены — этажность зданий, от которых зависит «неизвестно» по виду.** Очередь —
`data/curated/sochi_building_heights.csv` (272 здания, появится в PR лида по виду и солнцу).
Заполнять по Яндекс Картам и 2ГИС: `levels` или `height_m`, `source_url`, `checked_by`,
`checked_at`; начинать сверху — с зданий, от которых зависит больше всего окон. Первое —
`way/250086804` у Radisson. Заполненные строки расчёт берёт как проверенные человеком (D33).

## «Своё здание»

Корпус самого отеля — не препятствие для его вида. В сцене он отмечен `self_building: true`,
откуда отметка — в `self_source`:

- `v9_match` — корпус из сопоставления v9 (`results/facades/sochi_building_matches.jsonl`,
  статус `accepted_*`): у Radisson это 4 корпуса по адресу «65 лет Победы, 50», у COOCOOROOZA —
  `way/91225860` («Волжская, 18/16»);
- `contains_point` — точка отеля из Островка лежит внутри контура: у «Фрегата» это
  `way/53742336` (2 этажа, без имени).

Совпадение слов названия — только подсказка `name_match`, здание из препятствий оно не убирает:
«Отель Нептун» рядом с «Отелем Фрегат» — сосед. Поэтому башня `way/53742305` «LAVICON HOTEL
FREGAT» (15 этажей) в сцене — `name_match: true`, но не своё здание: у «Фрегата» в сопоставлении
v9 корпусов нет. **Лиду:** предложить её как ручное сопоставление (D33), чтобы «Фрегат» попал в
слой вида.

## Формат `scene_<city>_<hotel_id>.json`

```json
{
  "scene_version": "view-scene-osm@2",
  "hotel_id": "13736470",
  "hotel_name": "Radisson Collection Парадиз СПА, Сочи",
  "latitude": 43.39464, "longitude": 39.97605,
  "radius_m": 200.0,
  "source": {"provider": "OpenStreetMap", "license": "ODbL 1.0",
             "dataset": "research_notes/Расчёт характеристик/cohort/osm_sochi_extended.jsonl (сцена v9)",
             "release": "2026-10-22T20:21:33Z", "sha256": "096c3115…",
             "self_buildings": "сопоставление корпусов v9 (…) или точка отеля внутри контура"},
  "counts": {"buildings": 47, "self_buildings": 4, "with_height": 33, "with_levels": 33,
             "nearest_m": 63.1},
  "obstacles": [
    {"osm_id": "way/207598815", "name": "Radisson Collection", "self_building": true,
     "self_source": "v9_match", "name_match": true, "building": "yes",
     "distance_m": 31.4, "azimuth_deg": 23.6, "height_m": 27.0, "height_source": "levels_x3m",
     "levels": 9.0, "footprint_m2": 5203.2}
  ]
}
```

- `distance_m`, `azimuth_deg` — от точки отеля на центр контура (среднее вершин), 0° север,
  90° восток; стороны — от точки, а не от фасада;
- `height_source`: `height` (числовая высота в OSM), `levels_x3m` (этажность × 3 м), `missing` —
  высоты нет, и она **не выдумывается**;
- `counts.nearest_m` — ближайшее **чужое** здание;
- здания-отношения (`relation/…`, мультиполигоны) тоже в сцене.

## Чего в сцене нет

Контуры даны целиком, а расчёт вида работает по **сегментам фасада** и окнам:
`subject_level = facade_physical_floor`, `subject_id = "<здание>:<фасад>:floor<N>"` — это делает
расчёт лида. Описание окружения по карте Яндекса для тех же трёх отелей —
`tests/eval/view_surroundings_map.csv`; это не проверка вида из окна (этажа, моря и заката в нём
нет).

## Пересобрать

```bash
python -m calculators.view_scene --city sochi                    # выгрузка из материалов расчётов
python -m calculators.view_scene --hotels 13736470 --radius 300 \
    --extract "<папка проекта>/research_notes/Расчёт характеристик/cohort/osm_sochi_extended.jsonl" \
    --matches "<папка проекта>/research_notes/Расчёт характеристик/results/facades/sochi_building_matches.jsonl"
```

Выгрузка и сопоставление v9 лежат в материалах расчётов рядом с репозиторием (как у
`pipeline/build_view_sun.py`). Без выгрузки сцена собирается из закоммиченных ответов
`data/scenes/cache/osm_map_*.json` (три отеля показа, 26.10; зданий-отношений там нет).
Массовое чтение API редактирования OSM (api.openstreetmap.org) политика OSMF запрещает —
сетевого пути в модуле нет.
