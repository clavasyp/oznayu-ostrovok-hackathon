# Каталог Островка: Москва и Большой Сочи

Публичные страницы отелей ostrovok.ru — база каталога для городов фокуса (D36): отели, категории номеров, удобства, правила, отзывы на странице.

## Основание

- **D24:** данные Островка — обязательный источник, канал — сайт.
- **24.10.2026:** организаторы разрешили автоматизированный сбор (со слов пользователя; запрос был в чате хакатона).
- `robots.txt` разрешено не учитывать (организаторы, 23.10).

## Как собираем

Скрипт — `tools/collect.py`. Основа — сборщик Codex из v5: `research_notes/Данные Островка и набор городов/site_data/scripts/collector.py`.

1. **Список адресов** (`sitemap`).
   - Индекс `https://ostrovok.ru/sitemap.xml` → 56 частей по ~50 тыс. адресов → отбор страниц отелей России с токенами города:
     - **Москва:** `moscow`, `moscow_skolkovo_neighborhood`;
     - **Большой Сочи (D28):** `sochi`, `adler`, `sirius`, `krasnaya_polyana`, `krasnopolyanskoe`, `lazarevskoe`, `loo`, `dagomys`, `khosta`, `esto-sadok`, `vardane`, `golovinka`, `veseloe`, `polyana`, `big_sochi_(sochi_and_vicinity)_kudepsta_neighborhood`.
   - AMP-копии не берём.
   - Если часть sitemap не скачалась — пробел закрывается списком v5 от 23.10, но только для базовых токенов. Какие части не скачались — в `manifests/sitemap_summary.json`.
2. **Страницы** (`pages`).
   - Один поток, не чаще 1 запроса в 1,1 с, честный User-Agent.
   - Без входа в аккаунт, прокси и обхода защиты.
   - При 401 / 403 или странице проверки — остановка с `manifests/STOP.json`.
   - **Переезд страницы отеля** (301 / 308 на другую страницу отеля) — открываем новый адрес. **Редирект на выдачу** означает, что адрес устарел: записываем и не открываем.
   - Докачка: уже собранные адреса повторно не запрашиваются.

## Что лежит в `snapshot_2026-10-24/`

| Путь | Что |
|---|---|
| `urls.csv` | Список адресов: город, токен, `mid` из адреса, ссылка, часть sitemap |
| `manifests/http.jsonl` | Журнал каждого запроса: время, статус, размер, sha256, Location |
| `manifests/pages.jsonl` | По каждой странице: статус, итоговый адрес, `masterId`, число категорий (`rgHash`), есть ли отзывы, пути к файлам |
| `raw/<xx>/<sha256>.html.gz` | HTML страницы как получен (gzip); sha256 — от несжатого тела |
| `next/<xx>/<sha256>.json.gz` | `__NEXT_DATA__` страницы — основной вход коннектора `ostrovok_site` |
| `manifests/sitemap_summary.json` | Сколько адресов по городам и токенам, какие части sitemap не скачались |

## Оговорки

- **Sitemap — только SEO-подмножество.** В выдаче сайта отелей в 5–17 раз больше, в Москве 32 998 (v5). Полный список из выдачи — открытый вопрос, передан Codex (v11).
- **Город по токену адреса — метка рынка, а не граница.** После сбора отели фильтруются по координатам: Москва в границах города, Большой Сочи — по границе городского округа (D28). Токен `polyana` надо проверить по координатам.
- **`mid` в адресе ≠ `masterId` у ~13% страниц** (v5): ключ отеля — фактический `masterId` со страницы. В снимке 24.10 эвристическая сводка `pages.jsonl` расхождений не нашла.
- **Сводка `pages.jsonl` эвристическая:** `room_groups` — сколько раз встречается `rgHash`; `has_reviews` — есть ли ключ `reviews`, а не число отзывов. Факты — по `next/`.
- **Правила D26:** 0, пустой список, `false` и `UNSPECIFIED` = «неизвестно», а не «нет».

## Повторить

```bash
python3 -I tools/collect.py data/ostrovok_catalog/snapshot_<дата> sitemap
python3 -I tools/collect.py data/ostrovok_catalog/snapshot_<дата> pages
python3 -I tools/collect.py data/ostrovok_catalog/snapshot_<дата> status
```

## Пауза и продолжение

- **Остановка** — Ctrl+C или `pkill -INT -f tools/collect.py`: lock `manifests/RUNNING.lock` снимается сам. После `kill -9`, сбоя питания или выключения ПК посреди сбора lock остаётся. Если `pgrep -fl collect.py` ничего не находит, его можно удалить вручную.
- **Продолжение** — та же команда `pages`: адреса, уже записанные в `manifests/pages.jsonl`, пропускаются. `sitemap` повторно не запускать — он перезапишет `urls.csv`.
- **Фоном, чтобы Mac не уснул:** `nohup caffeinate -i python3 -I tools/collect.py <снимок> pages >> <снимок>/manifests/run_pages.log 2>&1 &`. Ход сбора — `tail -f <снимок>/manifests/run_pages.log`.
- **Конец:** `manifests/DONE.json` — пройдено всё; `PARTIAL.json` — что-то осталось. Lock исчезает и при ошибке, поэтому сам по себе он не значит, что сбор завершён.
