**Бейджи** — две оси:
- **пригодность:** known / unknown / conflict / stale / not_applicable;
- **происхождение:** `ostrovok_content` / hotelier / computed / guest_report / photo_observation / estimate.

Плюс `candidate` и `research_only`. Подписи:
- «Опубликовано Островком • снимок…»;
- «Из описания» / «Из названия категории»;
- «Данные OpenStreetMap • версия…»;
- «Согласуются два источника»;
- «Гость сообщил»;
- «Наблюдение по фото»;
- «Подтверждено отельером»;
- «Вычислено» / «Оценка»;
- «Источники расходятся» / «Нужно уточнить» / «Данные устарели».

**Анкета с предзаполнением:** найденное значение, цитата и дата как **предложение** + «верно / исправить / различается / не знаю». По каждому семейству — что предзаполнить, а что спросить. Например:
- **H01 / H03:** корпус и правило счёта;
- **вид и балкон:** корпус, этаж, фасад, все варианты, приватность, можно ли закрепить;
- **кондиционер и blackout:** управление и все проёмы;
- **питомцы:** вид, вес, сумма на даты;
- **маломобильные:** размеры и непрерывный маршрут.

Для D17 — таблица пар «часть здания × этаж × окна» + «есть ли номера вне таблицы?» + уровень гарантии.

## Оценка Claude

- **Проверил по сохранённым файлам:** `stage_stats.csv` — 1813 → 1854 → 1882 → 1887 и 5 конфликтных групп; `claims_all_frozen.jsonl` — **6090 строк**; QA50 n=50. Всё совпадает с отчётом.
- **Главный практический вывод:** дешёвый и реальный прирост дают **названия категорий и тексты описания Островка** — особенно **вид на море (0 → 32)** и балкон. Внешние источники почти ничего не дали на небольшой панели (OSM +5 атомов на 3 объектах), большинство реестров недоступны или без прав. **Фото и отзывы — 0 пригодного прироста.** Значит, главный путь к полноте по номерам — **анкета отельера с предзаполнением**, а не новые источники.
- **Важно для проекта:**
  1. ⚠ **Условия Островка (16.07.2026) запрещают автоматизированный сбор без разрешения оператора.** Наше основание — разрешение организаторов «со слов пользователя». **Нужно письменное подтверждение** (вопрос организаторам, D24).
  2. Принять в core: полный паспорт факта, оси уверенности, флаги пригодности, `counting_convention` для этажей, правило «домен ≠ независимость», бейджи происхождения, извлечение с цитатой + смысловая проверка + `abstain`.
  3. **LLM-извлечение без смысловой проверки опасно:** 5 из 50 ошибок при идеальных цитатах. В конвейер обязательно встраивать смысловые гейты и регрессионные тесты.
  4. W01 по Петербургу (пляж в 22–37 км) — пример, почему «известно» ≠ «полезно»: нужен порог применимости сценария.
- **Слабые места отчёта:** выборка смещена (апартаменты); внешняя панель всего 23; нет человеческой разметки; язык тяжёлый.
