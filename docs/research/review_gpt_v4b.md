## Что берём

1. **Две схемы AST:**
   - **полная локальная** — проверяется сервером;
   - **компактная рабочая** — отправляется модели.
   
   У Claude лимиты structured outputs: ≤ 16 union / nullable-полей и ≤ 24 необязательных, нет `oneOf`, рекурсии и `min` / `max`. В полной схеме отчёта 31 union-поле. Поэтому в компактной схеме:
   - `params` — список пар `{key, value}`;
   - логика — плоские OR-группы;
   - значения — текст, типизация на сервере.
2. **Поля AST** (из отчёта):
   - `status`: ready / needs_clarification / unsupported;
   - `city_id`, `date_context`, `party_context`;
   - `hard` / `soft` с `target` — характеристика каталога или поле размещения (`physical_floor.ordinal`, `placement_window.orientation`, `placement_set.guarantee_level`);
   - `scope`: level, `binding = same_placement / same_route / hotel`, quantifier;
   - `op`, `value`, `unit`, `params`;
   - `origin`: явно или по умолчанию, с `policy_id`;
   - `clarifications`, `unparsed_spans`.
   
   **Для жёстких условий уровня номера** валидатор требует `binding = same_placement` и `quantifier = all` (core §7.3).
3. **Объяснения через ID утверждений.** Код строит детерминированные утверждения с ID фактов. Модель возвращает только порядок ID и связки, значения подставляет код. Свободный текст выключен, пока его не проверяет валидатор. Это сильнее, чем просто проверять совпадение цифр.
4. **Спецификация из текста:** модель выдаёт JSON, сервер сериализует YAML (`safe_dump` + повторное чтение) → проверка по реестру → пробный прогон на 20 отелях → `active`.
5. **Ответ отельера.**
   - Поля: `answer_state` (answered / unknown / varies / refused / contradictory / not_applicable), quantifier, value, unit, conditions, `raw_quote`.
   - Позиции цитаты находит сервер, а не модель.
   - Происхождение и `is_simulated` проставляет сервер.
   - **Добавить тип «размещение категории»:** пары этаж × фасад, полнота, гарантия (D17).
6. **Имитатор отельера:**
   - закрытые профили с эталонной правдой, шум с фиксированным seed;
   - генератор не видит запрос гостя;
   - часть сценариев программная;
   - отдельные метрики разбора и вердикта.
7. **Безопасность:**
   - OWASP LLM Top 10 2025;
   - разбор запроса без инструментов;
   - маскировка ПД до отправки провайдеру;
   - инструменты только из allowlist;
   - не хранить в логах сырые промпты и thinking;
   - не класть ПД в enum и const схем (схема кэшируется до 24 ч).
   
   **Отзывы Островка** — вектор инъекций и ПД: обрабатываем только при сборке, с удалением ПД, в промпты поиска не подаём.
8. **Claude-специфика** (наши выводы):
   - effort задаётся явно (по умолчанию `medium`, для разбора замерить `low`);
   - кэширование промпта для статичного префикса — работает только через нативный SDK;
   - Batch API для подключения отелей: $0,082 вместо $0,164 за отель;
   - `stop_reason = refusal` → переход на запасного провайдера;
   - **адаптеры под каждого провайдера:** у GigaChat свой формат схемы, у Yandex схема несовместима с tools.
9. **Задержка.** Разбор за 2 с при всегда включённом thinking не обоснован. Порядок такой: компактный AST, кэш AST, сначала разбор правилами, LLM — только для остатка. Fast-режим — только по замеру.
10. **Стоимость (допущения, не замер):**
    - Claude ≈ $0,09 за поиск, около $0,056 с кэшем;
    - подключение отеля $0,164, через Batch $0,082;
    - Yandex ≈ 10 ₽ за поиск.

## Открытые вопросы к решению

1. **D21 и пользователи в России.** Правила Anthropic исключают использование людьми, физически находящимися в неподдерживаемом регионе, а не только размещение сервиса. Аудитория Островка — в основном Россия. Вариант: **запросы пользователей из РФ и РБ направлять в YandexGPT / GigaChat**, Claude — только для остальных и для сборки, если это допустимо. Это заодно упрощает 152-ФЗ. Решение пользователя (с юристом).
2. **`ostrovok_content` в обязательных условиях.** Это данные, которые отель передал Островку. Предложение: допускать как «заявление отельера через Островок» (наравне с `hotelier`), с бейджем «Данные Островка».
3. **Единое пространство ID характеристик.** Сейчас в core snake_case (`walk_to_beach`), в каталоге v3 коды (V01…). Предложение: `id` — snake_case, `catalog_code` — V01; список ID в схеме генерируется из реестра.
4. **OpenAI-совместимость:** отчёт предлагает свой шлюз с `/v1/chat/completions`. Пока не строим, ждём ответа организаторов (вопрос 3).
