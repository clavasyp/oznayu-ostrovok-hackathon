## Итог в трёх строках

- Отчёт аккуратный, выдуманных цифр нет: все 12 ключевых утверждений подтвердились (одно — по сути, без номера пункта).

## Блок 1. Каталог: 80 характеристик, 17 семейств

**Как устроен:**
- у ID один смысл навсегда: если входы хуже, падает уверенность или выходит «неизвестно», суррогат подставлять нельзя;
- **32 шаблона рецептов**, у каждого R1 и R2; R2 обязан давать тот же смысл и единицу;
- **рецепт доступен**, только если одновременно есть права, нужные поля, покрытие по месту и времени, пройден порог качества и смысл тот же;
- проверка идёт **по объекту, а не по городу**; уровень города A/B/C — только подсказка, где искать;
- **валидное «нет» останавливает цепочку**: к следующему рецепту ради «да» не переходят;
- два пригодных рецепта противоречат друг другу → это конфликт, а не «победа по порядку».

**Не взаимозаменяемы:**
- шум на фасаде и расстояние до дороги;
- шум на фасаде и тишина в номере;
- температура моря и разрешение купаться;
- сотовая ячейка и Wi-Fi в номере;
- отсутствие тега `steps` и проверенная доступность;
- отсутствие записей о преступлениях и «безопасно».

**Обозначения в таблице:**
- вид данных: А — готовые, Б — вычисляемые, В — от отельера;
- доступность в Барселоне / Сочи / Стамбуле:
  - `+` — работает везде;
  - `R1?` — есть кандидат-источник, нужна проверка;

## Блок 2. Список отелей

**Главное.** Полного, законного и свободно выгружаемого источника нет ни для одного города. Рабочая схема — версионированное объединение открытых POI, реестров и подтверждений отельеров. Полнота, юридический статус и звёзды учитываются отдельно.

**Глобальные источники:**
- **OSM** (ODbL).
- **Overture Places:**
  - релиз 2026-10-21.0, схема v2.0.0;
  - релизы живут 60 дней — нужен свой снимок с хешем;
  - поле `categories` удалено, вместо него `taxonomy` / `basic_category`;
  - OSM в Places нет; звёзд нет.
- **Foursquare OS Places:** только через Portal и токен; Apache 2.0.
- **Wikidata:** CC0, свойства P8733 (число номеров) и P10290 (звёздность) — для обогащения.

**Что брать из OSM:**
- основная выборка: `tourism=hotel|hostel|motel|guest_house|apartment|chalet|…`;
- `building=hotel` — только кандидат на проверку;
- `tourism=apartment` бывает одной квартирой;
- статусы `disused/abandoned/proposed/construction` исключаются;
- OSM `stars` — не официальная звёздность.

**Реестры по странам:**
- **Россия (дополнение подзадачи, в отчёте не было):**
  - реестр Росаккредитации **обязателен с 01.09.2025**, объекты вне реестра нельзя продавать через агрегаторы;
  - на 01.09.2025 в реестре 32 658 объектов, из них 23 791 действующий;
  - с 21.02.2025 агрегаторам открыт API (по вторичному источнику);
  - **для российских городов это почти полный легальный знаменатель. Вероятно, у Островка есть доступ — спросить организаторов.**
- **Турция:** поиск KTB включает и заявки, сам предупреждает о неполноте, экспорта нет. По Стамбулу XLSX-списка нет.
- **Дубай:** реестр DET существует, публичной построчной выгрузки нет, только запрос.
- **Беларусь и Грузия:** актуальный реестр не подтверждён.

**Хранение:**
- свой UUID отеля, `source_alias` (namespace, id, версия, first_seen, last_seen);
- `lodging_kind`;
- классификация отдельной таблицей: схема, орган, сырое значение, срок; звёзды разных систем не усреднять;
- происхождение по каждому полю.

**Слияние дублей:**
1. Неизменяемая загрузка с хешами.
2. Нормализация с сохранением оригиналов.
3. Отбор кандидатов через «или»: ID реестра, геососеди, адрес, домен или телефон, название.
4. Запреты на слияние: разные лицензии, разные корпуса, разные операторы.
5. Правила, затем скорер, затем «связать / на ревью / не связывать».
6. Только связь один к одному.
7. Журнал слияний и разделений с откатом.

Инструменты: Dedupe или Splink.

**Полнота** считается только для конкретных «территория × дата × типы».
- Знаменатель — реестр, если есть полная выгрузка. Иначе — независимый аудит по случайной выборке ячеек.
- Метод capture–recapture по OSM, Overture и FSQ запрещён: у них общие первоисточники.

## Блок 3. Категории номеров

**Сущности различаются:**
- `room_type` — физическая категория;
- `bed_configuration`;
- `occupancy_policy`;
- `rate_plan` / `commercial_product` — гарантия вида живёт здесь;
- `offer_snapshot`.

Внешние ID хранятся как `source_alias` со связью `exact / narrower / broader / overlap / rejected`.

**Размещение категории:**

`placement_set` (полнота: complete / partial / unknown) → `placement` (часть здания, физический этаж) → `placement_window` (фасад).

- **Нельзя хранить отдельные массивы фасадов и этажей.** Из «восток 1–3, запад 4–5» получатся ложные «восток-5» и «запад-1».
- **Гарантия:** `all_guaranteed`, `some_possible`, `on_request`, `exact_room`.
- **Жёсткое условие проходит**, только если набор полный и непустой, а каждое размещение даёт TRUE. Все условия запроса проверяются на одном и том же размещении.

**Ловушки поставщиков (проверено):**
- ETG `rg_ext.floor` — это класс, а не номер этажа: 1 пентхаус, 2 дуплекс, 3 цоколь, 4 мансарда;
- ETG `view` — перечисление;
- ETG `book_hash` живёт 24 часа;
- Expedia: выбор кроватей — только запрос, не гарантия;
- Booking `unit` — продаваемый тип, а не номер;
- **Островок продаёт категорию, а не номер.**

**Откуда законно брать категории:**
1. Анкета отельера или выгрузка из PMS / channel manager.
2. Сайт отеля: только факты, с проверкой ToS и прав.
3. Лицензированный канал.
4. Публичные страницы OTA — **нельзя**.

**Анкета:**
- предзаполненная, с кнопками «верно / исправить / различается / не знаю»;
- обязательный вопрос «есть ли номера вне таблицы?»;
- отдельный вопрос про гарантию;
- приоритет вопросов по пользе.

**Доля ответов отельеров не измерена нигде.** Отчёт предлагает эксперимент: 60 отелей, A/B-тест анкет, окно 14 дней.
