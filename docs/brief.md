## Трек «О!дин шаг до идеального отеля»

**Проблема.** Стандартные фильтры отвечают только на типовые вопросы: звёзды, завтрак, Wi-Fi, бассейн. Остальное пользователь ищет сам по отзывам, фото и панорамам, и на это уходят часы. Многое можно узнать заранее:
- вид из окна — по рельефу и высотам соседних домов;
- шум — по дорогам, барам и ж/д;
- остальное знает отельер.

Эти данные никто не собирает системно.

**Задача.** Прототип агентной системы, которая собирает уникальные характеристики отелей и номеров из открытых данных и у отельеров, систематизирует, хранит и показывает пользователю.
- Островок не даёт ни API, ни MCP, ни данных: всё собираем сами.
- Главная сложность — не придумать характеристику, а **достоверно её получить**: откуда она, насколько агент уверен, как её проверить, когда она устареет.
- «Спросить LLM, есть ли вид на море» — **не решение**.

**Обязательно:**
1. **Сбор характеристик.** Агент сам выбирает источники и инструменты. Хотя бы одна характеристика вычисляется по геоданным, а не берётся из текста.
2. **Диалог с отельером.** Если данных не хватает, агент задаёт вопрос, получает ответ в свободной форме и раскладывает его по полям. Отельера можно имитировать.
3. **Хранение и достоверность.** У каждого значения есть источник, уверенность и дата. Противоречия между источниками система замечает и разбирается с ними.
4. **Расширяемость.** Новую характеристику можно добавить без переписывания системы, например описав её текстом.
5. **Поиск по запросу.** Свободный текст вроде «тихий номер с видом на закат недалеко от моря».

**Дополнительно (бонусы):**
- объяснение выбора («закат виден, но только с 5-го этажа»);
- сравнение отелей и номеров;
- кабинет отельера: подтвердить или исправить значения, ответить на вопросы;
- актуализация устаревших данных («рядом построили дом и закрыли вид»);
- метрики качества на своей размеченной выборке: точность, покрытие, доля вопросов к отельеру.

**Ожидаемый результат.** Работающая система для набора отелей выбранного региона. **Трек рекомендует сосредоточиться на одном регионе**: «лучше глубоко проработать один, чем поверхностно охватить много». Наша система многогородская (D3), но **по городам выбрана глубина (D36): Москва и Большой Сочи — супер качественно**, остальные 6 городов — только автоматический слой, чтобы показать, что новый город собирается тем же конвейером.

Система должна быть рабочей, которая запускается по README без многочасовой загрузки данных: собранные данные лежат в репозитории. Если нужен ключ LLM — описать в README и приложить `.env.example`.

**Примеры источников из брифа** (не ограничение): OSM, DEM (SRTM, Copernicus), карты шума (Европа), GTFS, Open-Meteo, OpenAQ, OpenCellID, городские порталы (стройки, события), Wikidata/Википедия, Wikimedia Commons, Mapillary.

## Правила сдачи

- **Код** только в командном репозитории в организации `github.com/orgs/ostrovok-hackathon-2026`. В дедлайн ставим git-тег `submission` на последний коммит основной ветки.
- **Обязательные файлы:** `README.md`, `docker-compose.yml` в корне, `Dockerfile`, `.env.example`. Приватные зависимости и реестры запрещены.
- **Запуск:** `git clone` → `cp .env.example .env` → `docker compose up --build` без дополнительных аргументов → http://localhost:8080. Ориентир ≤10 минут на ноутбуке, без ручных доустановок.
- **Docker:**
  - приложение слушает 8080, в compose `8080:8080`;
  - сборка в несколько стадий, процесс не от root;
  - `/health` возвращает `{"status":"ok"}`, в compose есть healthcheck и `depends_on`;
  - версии образов зафиксированы, без `latest`;
  - логи в stdout;
  - POSIX sh;
  - `platform: linux/amd64` при сборке на Apple Silicon.
- **Данные:** секреты только в `.env`. Большие модели не кладём в git, используем OpenAI-совместимое API. Сидирование и миграции выполняются автоматически на старте или 1–2 командами из README.
- **README:**
  - описание и ссылка на видео (обязательно);
  - быстрый старт;
  - ресурсы, зависимости и переменные окружения со значениями по умолчанию;
  - сидирование;
  - маршруты (`/`, `/health`) и тестовые учётные данные.
- **Видео-скринкаст обязателен.** Выкладываем на публичный хостинг, проверяем, что открывается в режиме инкогнито.
- **Желательно:** Makefile (`up`, `down`, `seed`), `docker-compose.override.yml`, CI (сборка и линтер), ссылка на развёрнутый сервис.
- **Если проект не поднимется у жюри локально, его не оценят.**
