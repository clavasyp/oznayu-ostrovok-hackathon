## 4. Контракты — первое, что делает лид (сб, вечер)

От них зависят все остальные.

1. **Модель факта** (`core/models.py` + миграция): поля по `core.md` §2.2, имена — как в паспорте v9 (`research_notes/Расчёт характеристик/integrated/*_facts.jsonl`). Плюс `curated` и `curation_item` (D33).
2. **Интерфейс плагина:** калькулятор или коннектор получает объект и контекст города, возвращает `list[Fact]` и список попыток рецептов. Пример — E03.
3. **Схема AST запроса** — с Данилом: обязательное / желательное / уточнить / **вне каталога**. Основа — `core.md` §7.3.
4. **API на заглушках** из реальных фактов v9: `/api/search`, `/api/hotels/{id}`, `/api/hotelier/...`, `/api/cities/{id}/coverage`. Интерфейс сразу видит настоящие данные.
5. **Формат пакета города** (core §9) — с Севой. Факты, корпуса, геометрия для карты, `manifest.json` с источниками и хешами.

## 5. Критический путь

1. **Контракты (сб)** → работа всех остальных.
2. **Наш сбор каталога** (идёт, к утру вс) → коннектор Островка → каталоги Москвы и Сочи в БД.
3. **Связь отель ↔ корпус в Москве** → дороги, этажность, вид, противоречия в Москве.
4. **Высоты соседних зданий + размещение категорий от имитатора** → вид и солнце, главный пример трека.
5. **Доступ к данным карт** (способ и ключи выясняет v11) → транспорт, еда, часы, рейтинги.
6. **Пакет города + замер запуска ≤ 10 мин** → сдача.

## 8. Правила работы

- **Владение папками** — по разделу 3. В чужую папку — только через PR владельца.
- `main` защищён: маленькие PR, ревью лида, ветка `имя/задача`.
- **Синк 2 раза в день по 15 минут** (утро и вечер): что сделал, что блокирует.
- Каждая цифра — факт с паспортом. LLM не источник фактов (D8). Не называть проект «демо».
- Данные Островка — наш сбор, разрешение есть (D24). Данные карт — разрешены (D35); CAPTCHA и авторизацию не обходим.
- Отчёты Codex Claude читает целиком и кладёт выводы в `docs/`. Команда берёт скрипты из `research_notes/` и переносит в свои плагины.
