# agents/address/

Задача 3б (D33): связь «отель ↔ здание» для Москвы. В v9 с корпусами связаны 19 отелей из 50 —
без связи нет этажности, вида, солнца и шума у окна.

**Здесь только кандидаты.** Код предлагает здание с доказательством, решение о связи и геометрию
делает Сева, принимает человек. Ближайшее здание без совпадения адреса — не кандидат, а подсказка
(как в v9: «ближайший контур без полного адреса не принимается»).

## Что где

| Файл | Что |
|---|---|
| `normalize.py` | Адрес → тип улицы, название, порядковый номер, дом, корпус, строение, литера, владение. Отбрасывает страну, город, район, индекс, помещение, «formerly…». Название сравнивается по скелету латиницей: «Дорогомиловская» = «Dorogomilovskaya», «Анохина» = «Anohina» |
| `match.py` | Здания пакета (`buildings.jsonl.gz`, метки `addr:*` и `addr2:*`) → кандидаты для каждого отеля: строка `curation_item` (`kind = match_hotel_building`, core/db.py) |
| `llm.py` | Модель — только для адресов, которые правила не разобрали. Каждая часть ответа проверяется по исходной строке: цифр дома нет в строке или слова улицы нет — ответ отклоняется |
| `__main__.py` | `python -m agents.address --city moscow [--buildings FILE] [--out FILE] [--llm]` |

## Уверенность кандидата

| `confidence` | Когда | Минут на проверку |
|---|---|---|
| `high` | Улица и полный номер дома совпали, здание не дальше 300 м от точки Островка | 0,5 |
| `medium` | Тот же номер, но корпус / строение / литера расходятся; улица с опечаткой («Московкая»); или здание в 300–1500 м | 1,5 |
| `ambiguous` | Несколько зданий с этим адресом (части здания, тип улицы не назван: «Smolenskaya 10») | 3 |
| `low` | Адрес совпал, но здание дальше 1,5 км — скорее, неверна точка отеля | 3 |
| `none` | Адрес не разобран (нет номера дома) или здания с таким адресом нет; в доказательствах — 3 ближайших здания | 5 |

Полный номер дома — как в v9: «1» ≠ «1Б», «19/21» ≠ «19/21 к2», «219» ≠ «219/28».

## Доказательства (`evidence`)

- `hotel_address` — адрес Островка как есть и после разбора, что отброшено;
- `building_address` — метки OSM здания, разбор, совпадение улицы и дома, расстояние;
- `v9_link` — с каким зданием отель был связан в расчёте v9 (по фактам пакета) — для сверки;
- `nearest_buildings` — когда адрес не совпал: ближайшие здания, не кандидаты.

## Сейчас

- Адреса разобраны полностью: Москва — 49 из 50, Сочи — 88 из 89, Петербург — 50 из 50. Не
  разобраны адреса без номера дома («Ул.Марксистская») — номер не угадываем.
- Зданий OSM с адресами в репозитории нет (в пакет попадают только результаты). Кандидаты
  построятся, когда в пакете появится `buildings.jsonl.gz` с метками `addr:*` (Сева).
