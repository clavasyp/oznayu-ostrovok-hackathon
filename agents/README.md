# agents/

LLM: разбор запроса, агент-отельер и имитатор, объяснения, новая характеристика из текста.

Владелец: Данил. Изменения в чужой папке — через PR владельца.

**Главное правило (D8):** LLM не источник фактов. Модель переводит текст в структуру; значения,
позиции фрагментов, единицы и веса проставляет код; каждый ответ модели проходит схему и
валидатор. Без ключа всё работает правилами (офлайн-режим, с пометкой).

## Что где

| Папка | Что |
|---|---|
| `llm/` | Шлюз (D21): `anthropic` (Claude Opus 5.5, structured outputs, effort, серверный запасной путь при отказе) и `openai_compat` (YandexGPT / GigaChat). Проверка ответа pydantic-моделью, один повтор с ошибкой схемы, запасной провайдер. `fake.py` — для тестов |
| `catalog/` | `features.json` — словарь для разбора: 80 характеристик v9 (54 расчётные + 26 «только отельер») и поля размещения `floor`, `courtyard`. Поля значений с единицами, уровень, синонимы. У 26 вопросов отельеру поля — ровно `parsed_fields` (контракт `core/hotelier.py`). Значений характеристик нет |
| `search/` | Разбор запроса → `QueryAST` (контракт 3): правила (`rules.py`) → модель для остатка (`prompt.py`, компактная схема `compact.py`) → перевод в полный AST и проверка (`validate.py`). Дальше AST идёт в движок `core/search.py` |
| `hotelier/` | Агент-отельер: предзаполнение Островка к вопросам, имитатор по закрытым профилям (`profiles/`), разбор свободного ответа в поля вопроса (`agent.py`, `parse_answer.py`), разбор размещений категорий (`placement.py`). Факты, замены и противоречия делает `core/hotelier.py` (лид) |
| `eval/` | Точность разбора на эталонах `tests/eval/parse_reference.jsonl` |
| `schemas/` | JSON-схемы: полный AST, компактный AST для модели |

## Разбор запроса

```python
from agents.search import parse, parse_query

ast = parse("тихий номер с видом на закат недалеко от моря", "sochi")
outcome = parse_query(text, city_id)  # + notes (офлайн, неразобранное), problems, llm.usage
```

- **Порядок:** правила → если они покрыли весь текст, модель не зовём → иначе Claude по
  компактной схеме → `to_full_ast` (позиции в code points, типы и единицы, веса, привязка) →
  проверка → при любой неудаче модели — результат правил с пометкой.
- **Ничего не теряется (D34):** без характеристики — `out_of_catalog` с ближайшими контрактами
  (`nearby_place`, `trip_to_target`); неразобранные слова — `unparsed_spans`; выведенное, а не
  сказанное гостем — только `clarify`.
- **Частичное соответствие** («без лестниц» и «0 известных лестниц в OSM», «вид с кровати» и вид
  из окна) — только мягкое условие; обязательное частичное ещё и `out_of_catalog` → «Нужно
  уточнить», а не «Подходит».
- **Уровень номера** (`room_type`, `facade`, `placement`) → `binding = same_placement`,
  `quantifier = all` (D17).
- **Пороги политики** («недалеко» = 800 м, «тихо в номере» = LAeq ≤ 30 дБ(A), «10 минут
  пешком» = 800 м при 80 м/мин) — в начале `search/rules.py` и в `features.json`.

## Агент-отельер

```
GET  /api/hotelier/{id}/questions   26 вопросов + prefill («на Островке указано… верно?») и fields
POST /api/hotelier/{id}/simulate    {question_id | feature_id} → ответ имитатора (is_simulated)
POST /api/hotelier/{id}/answers     {question_id, answer_text, is_simulated[, ast]}
                                    → агент разбирает текст в fields → core/hotelier → факты;
                                      в ответе `agent`: поля с цитатами, отклонённое, уточнение
```

- **Только текст** в `answers` (без `fields`, `dont_know`, `placements`) разбирает агент: поля —
  ровно `parsed_fields` вопроса, «не знаю» → `dont_know`. Не понял — текст остаётся
  `answered_unparsed`, факта нет, есть уточняющий вопрос.
- **«Есть / нет»** там, где у вопроса нет поля да / нет, — через значение поля: `lift_id`,
  `hvac_type`, `connector`, `access`… = `"none"` (нет) или `"present"` (есть без уточнений);
  `parking_owner = "own"`; `species` = `dog` / `cat` / `dog_cat` / `any` / `none`.
- **Проверка** одна для модели и правил: цитата найдена в ответе, число есть в самой
  цитате («да, лифт есть» не заполняет размеры), единицы и область сходятся.
- **«Для части номеров»** в поля не отправляется — только текст и уточнение: такой ответ не
  должен закрыть обязательное условие.
- **Размещения** (`placement.py`): «окна на юго-запад, с 3 по 8 этаж» → пары «здание × этаж ×
  окна» для `placements`, но только когда известны `building_id` и фасад на эту сторону. В пакетах
  городов категорий и корпусов пока нет — размещения не отправляются, без догадок.
- Профили имитатора — **эталонная правда для показа, не факты**: Radisson (`13736470`),
  «Архитектор» (`10012084`), Cosmos (`9986868`). Имитатор не видит запрос гостя.
