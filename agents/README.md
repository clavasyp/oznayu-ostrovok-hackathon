# agents/

LLM: разбор запроса, агент-отельер и имитатор, объяснения, новая характеристика из текста.

Владелец: Данил. Изменения в чужой папке — через PR владельца.

**Главное правило (D8):** LLM не источник фактов. Модель переводит текст в структуру; значения,
позиции фрагментов, единицы и веса проставляет код; каждый ответ модели проходит схему и
валидатор. Без ключа всё работает правилами (офлайн-режим, с пометкой).

## Что где

| Папка | Что |
|---|---|
| `llm/` | Шлюз (D21): `anthropic` (Claude Opus 5.5, structured outputs, effort, серверный запасной путь при отказе) и `openai_compat` (YandexGPT / GigaChat). Проверка ответа pydantic-моделью, один повтор с ошибкой схемы, запасной провайдер. `fake.py` — для тестов |
| `catalog/` | `features.json` — словарь для разбора: 80 характеристик v9 (54 расчётные + 26 «только отельер») и поля размещения `floor`, `courtyard`. Поля значений с единицами, уровень, синонимы. Значений характеристик нет |
| `search/` | Разбор запроса → `QueryAST` (контракт 3): правила (`rules.py`) → модель для остатка (`prompt.py`, компактная схема `compact.py`) → перевод в полный AST и проверка (`validate.py`) |
| `hotelier/` | Анкета с предзаполнением Островка, имитатор по закрытым профилям (`profiles/`), разбор ответа в поля, факт `simulated_hotelier` / `hotelier`, противоречия с карточкой, размещение категорий |
| `eval/` | Точность разбора на эталонах `tests/eval/parse_reference.jsonl` |
| `schemas/` | JSON-схемы: полный AST, компактный AST для модели |

## Разбор запроса

```python
from agents.search import parse, parse_query

ast = parse("тихий номер с видом на закат недалеко от моря", "sochi")
outcome = parse_query(text, city_id)  # + notes (офлайн, неразобранное), problems, llm.usage
```

- **Порядок:** правила → если они покрыли весь текст, модель не зовём → иначе Claude по
  компактной схеме → `to_full_ast` (позиции в code points, типы и единицы, веса, привязка) →
  проверка → при любой неудаче модели — результат правил с пометкой.
- **Ничего не теряется (D34):** без характеристики — `out_of_catalog` с ближайшими контрактами
  (`nearby_place`, `trip_to_target`); неразобранные слова — `unparsed_spans`; выведенное, а не
  сказанное гостем — только `clarify`.
- **Частичное соответствие** («без лестниц» и «0 известных лестниц в OSM», «вид с кровати» и вид
  из окна) — только мягкое условие; обязательное частичное ещё и `out_of_catalog` → «Нужно
  уточнить», а не «Подходит».
- **Уровень номера** (`room_type`, `facade`, `placement`) → `binding = same_placement`,
  `quantifier = all` (D17).
- **Пороги политики** («недалеко» = 800 м, «тихо в номере» = LAeq ≤ 30 дБ(A), «10 минут
  пешком» = 800 м при 80 м/мин) — в начале `search/rules.py` и в `features.json`.

## Агент-отельер

```
GET  /api/hotelier/{id}/questions   26 вопросов с предзаполнением + адресные о размещении
POST /api/hotelier/{id}/simulate    {feature_id[, room_type_id]} → ответ имитатора (is_simulated)
POST /api/hotelier/{id}/answers     {feature_id, answer_text, is_simulated[, room_type_id]}
                                    → поля с цитатами, отклонённое с причинами, уточнение, факт
```

- Профили имитатора — **эталонная правда для показа, не факты**: Radisson (`13736470`),
  «Архитектор» (`10012084`), Cosmos (`9986868`). Имитатор не видит запрос гостя.
- Проверка ответа одна для модели и правил: цитата найдена в ответе, число есть в самой
  цитате («да, лифт есть» не заполняет размеры), единицы и область сходятся.
- «Для части номеров» обязательное не закрывает; расхождение с карточкой Островка того же
  смысла — противоречие `detected`, и до решения условие «Нужно уточнить».
