# tests/eval/ — разметка и метрики

Своя размеченная выборка и честные метрики качества: точность, покрытие, доля «неизвестно»,
доля вопросов к отельеру. Владелец: Лера.

| Файл | Что |
|---|---|
| `annotations.csv` | 34 случая Codex (30 разных контекстов + 4 дубля) с нашим ответом и эталоном Codex. Человеческие колонки: `verdict`, `evidence_url`, `evidence_date`, `minutes_spent`, `annotator`, `checked_by`, `notes` |
| `build_annotations.py` | пересобирает машинные колонки `annotations.csv` из `validation/cases.csv`, фактов v9 и `ai_checks.json`; существующую разметку без `--force` не трогает |
| `ai_checks.json` | черновик проверки ИИ-ассистента по 34 случаям — предложение вердикта, не подпись человека |
| `metrics.py` | считает метрики по пакету города, своей разметке, расстояниям и разбору запросов |
| `baseline.md` | срез метрик по Сочи — вывод команды ниже |
| `distances.csv` | 11 замеров пешего маршрута до берега по Яндекс Картам против W01 |
| `view_surroundings_map.csv` | окружение трёх отелей показа по карте Яндекса, 8 сторон — **не** проверка вида из окна |
| `station_note.md` | станция 37099 против ячейки ERA5: границы применимости климата, не точность |
| `compare_v9.py` | сверка калькуляторов с расчётами v9 на общих отелях |
| `check_reasons.py` | у каждого кода «неизвестно» наших калькуляторов есть текст для экрана |
| `rating_rules.md` | черновик правил рейтингов с карт (место — `specs/`, владелец лид) |

## Разметка

```bash
python tests/eval/build_annotations.py     # только если разметки ещё нет; --force перезапишет
```

`verdict` — одно из трёх: `верно`, `неверно`, `не проверить`. «Не проверить» — это не «верно»:
случай попадает в отдельную долю и в точность не входит. У каждого проверенного случая должна быть
ссылка-доказательство (`evidence_url`) и дата (`evidence_date`) — иначе это не эталон, а мнение.

`checked_by` — кто проверил. Если вердикт сделал ИИ-ассистент, так и пишем: «проверил
ИИ-ассистент, принято <кто> <дата>» (D33, D41) — это не проверка человеком. `minutes_spent` —
только минуты, засечённые человеком. Сейчас все 34 случая — «проверил ИИ-ассистент, принято
dedokik 25.10», минут нет.

## Метрики

```bash
python tests/eval/metrics.py --city sochi --annotations tests/eval/annotations.csv \
    --distances tests/eval/distances.csv --out tests/eval/baseline.md
```

Факты и вопросы берутся из пакета города по манифесту — **все** файлы `kind: facts` (после слоя
«вид и солнце» их два) и `kind: questions`, как при загрузке в базу у жюри. `--facts` и
`--questions` — только для других файлов; `app/fixtures/questions.json` — заглушка показа, для
метрик не годится (из неё выходило «вопрос нужен 11 из 89»). Разбор запросов —
`--parse <CSV из python -m agents.eval.parse_eval --csv>`.

| Метрика | Знаменатель | Как читать |
|---|---|---|
| покрытие | отели города | доля отелей с любым значением, включая оценки |
| покрытие без оценок | отели города | доля отелей со значением, которое может закрыть обязательное условие (D18) |
| доля «неизвестно» | строки фактов | где мы честно не знаем; неизвестное не равно «нет» |
| доля оценок | строки фактов | значения ниже порога публикации (D18) — в обязательных условиях не участвуют |
| доля вопросов отельеру | отели города | где без отельера не обойтись; из пакета города, как у жюри |
| точность | случаи с эталоном | `верно / (верно + неверно)`; «не проверить» в знаменатель не входит |
| ошибка в метрах | пары «наш путь — эталонный» | MAE, медиана и p90 модулей, медиана разности со знаком (`--distances`, колонки `our_m`, `reference_m`) |
| разбор запросов | условия запроса | точность и полнота отдельно для обязательных и желательных: найдено / (найдено + лишнее), найдено / (найдено + пропущено); сверяется **только код характеристики** — оператор, порог и отрицание нет |

Правила, которые нельзя нарушать в питче:

- совпадение с v9 и прохождение проверок формата — проверка переноса, а **не** точность;
- у каждой цифры — знаменатель и объём выборки: «покрытие 100%» — это «89 отелей пакета Сочи»,
  а не весь каталог; медиана модулей и медиана разности со знаком — разные числа;
- оценка (D18) не закрывает обязательное условие: на слайд — «покрытие без оценок»;
- разбор запросов — «условие найдено по коду характеристики», а не «точность понимания запроса»;
- вид и солнце: «вид сверен с эталоном» **не** говорим — `view_surroundings_map.csv` описывает
  окружение по карте в 200 м от точки Островка, этажа, моря и заката в нём нет;
- разметку ИИ не выдаём за проверку человеком (D33);
- цифры пересчитываются после каждой правки калькулятора, а не переносятся из прошлого слайда.

## Сверка с v9

```bash
python tests/eval/compare_v9.py --cities sochi moscow --features C01 C02 C03 B02
```

Сравнивает факты, посчитанные текущими калькуляторами, с фактами v9 по ключу
(отель, характеристика, месяц). Возвращает 1 при любом расхождении. Для B02 сверяется численное
ядро на тех же ячейках модели: отбор «отель → пляж» — это геометрия Севы, и в v9 он заморожен.

## Что здесь ещё не измерено и почему

- **Вид и солнце (V01, V05)** — независимого эталона нет. `view_surroundings_map.csv` — окружение
  по карте, по сторонам от точки отеля, а не от фасада; факты лида им не проверяются. Для
  проверки нужен эталон по окнам: `subject_id` «здание:фасад:floorN», ожидаемое да / нет /
  не проверить, источник с датой (фото из окна, панорама с высоты).
- **Разбор запросов** — 52 эталона в `parse_reference.jsonl`, построчный CSV даёт
  `python -m agents.eval.parse_eval --csv`. Порог и направление в эталоне не записаны, поэтому
  и метрика их не сверяет.
- **Точность разметки 34 случаев** — не измерена: эталон Codex описывает другой смысл (станция на
  берегу против ячейки 0,25°, тот же OSM-след, фото без ракурса), все вердикты — «не проверить».
- **Точность климата и моря** — есть только пространственная сверка со станцией
  (`station_note.md`, независимый эталон того же смысла отсутствует), поэтому публикуются
  покрытие и явные границы применимости.
