# Правила рейтингов с карт (черновик)

Для мягких пожеланий вида «вкусно», «хорошие завтраки рядом», «приличные бары».
Владелец правил — Лера; место после ревью — `specs/` (владелец лид), тогда же расчёт в
`calculators/` делает Сева.

Основание: **D35** (Google Maps, 2ГИС, Яндекс Карты разрешены организаторами, слой `poi` даёт
рейтинг и число оценок) и **D18** (оценка не закрывает обязательное условие).

## 1. Что считается рейтингом

Только пара «**рейтинг + число оценок + дата снятия**» у конкретного объекта, найденного на карте:

```json
{
  "place_id": "yandex:1122334455",
  "rating": 4.8,
  "ratings_count": 1240,
  "snapshot_at": "2026-10-24",
  "provider": "yandex_maps",
  "url": "https://yandex.ru/maps/org/...",
  "matched_by": "name+address+coordinates<=150m"
}
```

Рейтинг без числа оценок — не факт, а картинка: в мягкое ранжирование не идёт.

## 2. Порог публикации

| Число оценок | Что делаем |
|---|---|
| < 20 | не публикуем рейтинг вообще: «нужно уточнить» |
| 20–49 | публикуем со статусом `estimate` и пометкой «мало оценок» |
| ≥ 50 | `observed` с датой снятия; можно в мягкое ранжирование |
| ≥ 200 | высокая уверенность, бейдж без оговорок |

Порог 50 — рабочая гипотеза: на ней рейтинг перестаёт прыгать от одного отзыва. Если Сева принесёт
распределение по нашим городам, порог пересматриваем по данным, а не по вкусу.

## 3. Свежесть

- дата снятия хранится всегда (`snapshot_at`), в бейдже показывается как «на 24.10»;
- снимок старше **90 дней** — `estimate` с причиной `rating_snapshot_stale`;
- объект, у которого все оценки старше двух лет, рейтингом не считается: место могло измениться.

## 4. Несколько карт на один объект

- **не усредняем** рейтинги между картами: шкалы и аудитории разные, среднее — выдуманное число;
- основной источник — тот, где больше оценок; остальные хранятся в паспорте как `additional_sources`;
- расхождение основных рейтингов **> 0,7** — «нужно уточнить» с причиной `rating_sources_disagree`
  (значит, объекта сравнения, скорее всего, два разных);
- один объект = один `place_id` на карту; склейка по имени без координат запрещена.

## 5. Сопоставление объекта

Место с карты годится для отеля, если совпали: имя (нормализованное, без «кафе», «ресторан»),
адрес (дом) **и** расстояние ≤ 150 м. Иначе — не сопоставлено, и это не «нет такого места».

## 6. Текст бейджа

```
4,8 в Яндекс Картах, 1 240 оценок, на 24.10
4,3 в 2ГИС, 34 оценки — мало оценок, на 24.10
Рейтинг не публикуем: 12 оценок
```

Правила текста: десятичная запятая, разделитель разрядов — неразрывный пробел, дата — `дд.мм`,
источник назван всегда, оговорка о числе оценок — сразу после числа.

## 7. Чего рейтинг не означает

- «4,8» не значит «вкусно»: это агрегат по впечатлениям, а не проверка кухни. В ответе гостю
  рейтинг — **косвенное** свидетельство (`mapping: partial`), а не прямое «да»;
- рейтинг заведения не переносится на отель и наоборот;
- отсутствие рейтинга — не «плохо»: это «неизвестно» (D5);
- рейтинг никогда не закрывает обязательное условие (D18): «обязательно вкусный завтрак» →
  «нужно уточнить», а не «подходит».

## 8. Что мерить

- покрытие: доля отелей, у которых есть хотя бы одно сопоставленное место с рейтингом;
- доля «мало оценок» и доля `rating_sources_disagree` — это честная цена правила;
- точность сопоставления — вручную на 20–30 объектах: `annotations.csv`, вердикт
  «верно / неверно / не проверить», у каждого случая ссылка и дата.
