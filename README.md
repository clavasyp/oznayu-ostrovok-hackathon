# О!знаю — команда vaibovovka

Ostrovok Hackathon 2026, трек «О!дин шаг до идеального отеля».

Гость пишет пожелание обычным текстом — например, «тихий номер с видом на закат недалеко от моря». Система подбирает номера и по каждому условию показывает «Подходит», «Нужно уточнить» или «Не подходит», а также откуда это известно. Мы знаем об отелях то, чего нет в карточке: считаем по геоданным, спрашиваем отельера, собираем из открытых источников и карт. У каждого факта есть паспорт: источник, способ получения, дата, уверенность.

Города: Москва и Большой Сочи — полная глубина; ещё 6 городов — автоматический слой.

> Видео — ссылка появится здесь к сдаче (29.10, 10:00 МСК).

## Быстрый старт

```bash
git clone https://github.com/ostrovok-hackathon-2026/vaibovovka.git
cd vaibovovka
cp .env.example .env
docker compose up --build
```

Открыть http://localhost:8080. Миграции и загрузка данных идут сами (сервис `init`), других команд не нужно. Нужны Docker с Compose v2 и интернет для первой сборки: Docker Hub, GHCR, PyPI, npm.

## Что поднимается

| Сервис | Что делает | Когда готов |
|---|---|---|
| `db` | PostgreSQL 16 + PostGIS 3.6 (`postgis/postgis:16-3.6`), данные в томе `pgdata` | `pg_isready` по TCP |
| `init` | Миграции Alembic и загрузка пакетов городов из `packs/`; уже загруженный пакет повторно не грузится | завершился с кодом 0 |
| `app` | API и интерфейс на порту 8080 | `/health` → `{"status":"ok"}` |

Образ приложения один на `init` и `app`, сборка в три стадии (`Dockerfile`): интерфейс (Node 24) → зависимости Python строго по `uv.lock` → итоговый образ без инструментов сборки, процесс не от root. Версии образов зафиксированы. Все сервисы — `linux/amd64`, на Apple Silicon Docker Desktop запускает их через эмуляцию.

## Маршруты

| Путь | Что |
|---|---|
| `/` | Интерфейс. Пока он не собран — страница со ссылками на API |
| `/health` | Готовность: `{"status":"ok"}`; пока идёт запуск — 503 и фаза |
| `/live`, `/ready` | Процесс жив; то же, что `/health` |
| `/docs` | Все маршруты API (OpenAPI) |
| `/api/...` | Города и покрытие, отели и факты, поиск, вопросы отельеру, противоречия |

Входа нет: кабинет отельера и админка открыты, тестовые учётные данные не нужны.

## Как проверить за 5 минут

1. **Поиск текстом с доказательствами.** Город «Большой Сочи», запрос «тихий номер с видом на закат недалеко от моря, 15 ноября». Закат посчитан по окнам: этаж и сторона каждого фасада, рельеф, высоты соседних зданий. В объяснении видно, например, «окна на юго-запад, этажи 7–14, подходят не все окна». Где номер, знает только отель, поэтому статус «Нужно уточнить», а вопрос отельеру уходит одной кнопкой.
2. **Агент добывает то, чего нет в каталоге.** Запрос «обязательно рядом итальянский ресторан». Такой характеристики в каталоге нет, но система берёт категорию места и считает расстояние по местам города на запросе. «Подходит» — с названием места и расстоянием. «Нет» система не говорит, ведь места на картах отмечены не все: такие отели получают «Нужно уточнить». Слова о качестве («хорошие», «вкусные») честно остаются «неизвестно» — рейтингов у нас нет.
3. **Диалог с отельером.** Radisson Collection Парадиз, запрос «обязательно можно с собакой». Сначала «Нужно уточнить». Ответ в кабинете отельера (песочница отвечает за имитатора) раскладывается по полям, и выдача пересчитывается: «Подходит». Ответ о размещении номеров (вкладка «Где окна номеров», например Grand Karat: «окна на юго-запад, с 9 по 15 этаж. Других вариантов нет.») становится этажами и стенами корпуса. С датой 15 ноября закат из окна переходит из «Нужно уточнить» в «Подходит».
4. **Новая характеристика текстом.** Панель команды → «Новая характеристика»: «сколько кафе в 500 м». Дальше черновик спецификации, проверка, пробный расчёт и «Включить». Характеристика считается для всех отелей Москвы и Сочи, факты с паспортом попадают в базу. Поиск сразу понимает её в запросе «много кафе». Код не меняется. То же можно начать из журнала «Что спрашивают, а мы не знаем» кнопкой «Сделать характеристику».

## Переменные окружения

Все — в `.env.example`. Без `.env` compose берёт те же значения по умолчанию. Секреты — только в `.env`, он не попадает ни в git, ни в образ.

| Переменная | По умолчанию | Что |
|---|---|---|
| `DATA_MODE` | `db` | `db` — база, куда `init` загрузил пакеты городов; `fixtures` — заглушки из фактов v9 без базы (для интерфейса без Docker) |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | `oznayu` | База; адрес для `init` и `app` compose собирает из них |
| `LLM_PROVIDER` | `anthropic` | LLM-шлюз: `anthropic` — основной, OpenAI-совместимый — запасной |
| `LLM_MODEL` | `claude-opus-5-5` | Модель |
| `LLM_API_KEY` | пусто | Ключ LLM |
| `LLM_BASE_URL` | пусто | Адрес OpenAI-совместимого API |
| `DATABASE_URL`, `PACKS_DIR` | см. `.env.example` | Только для запуска вне Docker |
| `WARMUP` | `1` | После загрузки пакетов прогреть кеш базы запросами показа в фоне — первый поиск быстрее |

**Ключ модели.** Модель только разбирает запрос, раскладывает ответы отельера и пишет объяснения по нашим фактам; фактов она не придумывает (D8). Без ключа всё работает на правилах, интерфейс помечает офлайн-режим. Любой OpenAI-совместимый API подключается так: `LLM_PROVIDER=openai_compat`, `LLM_BASE_URL=<адрес API>`, `LLM_MODEL=<модель>`, `LLM_API_KEY=<ключ>`. Ключ Anthropic подключается с `LLM_PROVIDER=anthropic`, `LLM_API_KEY=<ключ>`.

## Данные и сидирование

Сидирование автоматическое. При каждом запуске `init` применяет миграции и грузит пакеты городов из `packs/` (формат — `packs/FORMAT.md`), сверяя хеши из `manifest.json`; строки идут потоковым `COPY`, `init` печатает прогресс по видам файлов. Вручную — `make seed` или `docker compose run --rm init`. Тяжёлые расчёты делаются заранее: в пакетах только результаты. Уже загруженный пакет повторно не грузится (повторный `init` — около секунды).

Время загрузки (27.10): `init` на чистой базе — 86,5 с на все 8 городов (Москва 31,5 с, Сочи 47,3 с; Python на Mac с Apple Silicon, PostGIS в Docker в эмуляции amd64, параллельно шёл другой тяжёлый расчёт). До правок D41 — 832 с. Плюс сборка образа при первом `docker compose up --build`.

Сейчас в `packs/` — 8 городов, 7206 отелей, 383 702 факта с паспортом:

- **Москва и Большой Сочи — полная глубина (D36):** полный каталог Островка (снимок 24.10, `pipeline.build_packs`; категории шести отелей показа — снимок 27.10, `pipeline.supplement_categories`): 4211 и 2695 отелей, 22 011 категорий номеров. Георасчёты по всему каталогу, корпуса и фасады, места рядом и станции (D34, D39), очередь ручной проверки D33.
- **Ещё 6 городов — автоматический слой из расчётов v9:** по 50 отелей.
- Вопросы отельеру с предзаполнением — у каждого отеля Москвы и Сочи (вне когорты v9 — по шаблонам v9, предзаполнение — заявления страницы Островка), покрытие по 54 характеристикам, сверка с карточкой Островка.

Пересборка:

- шесть автоматических городов — `python -m pipeline.build_v9_packs --city spb --city kazan …` (сборщик v9 не перезаписывает пакет другой сборки);
- Москва и Сочи — цепочка `build_v9_packs --out /tmp/v9` → `build_packs --v9-packs /tmp/v9` → `calculate_city` / `calculate_moscow` → `finalize_packs` → `supplement_categories` → `publish_packs` (нужны профиль `builder` и исходники: снимки Островка из релизов данных, срезы OSM, растры; команды — `connectors/README.md`);
- после пересборки — `make audit` (офлайн-аудит пакетов, отчёт в `pipeline/reports/`) и `make test-packs` (поставляемые пакеты в настоящей PostGIS).

Без Docker API может работать на заглушках из тех же фактов v9 (`app/fixtures/`, `DATA_MODE=fixtures`).

## Разработка

```bash
uv sync --extra api --extra llm                          # окружение приложения; группа dev ставится сама
uv sync --all-extras                                     # + сборка пакетов городов (Сева, Лера, лид)
DATA_MODE=fixtures uv run uvicorn app.main:app --port 8080  # API на заглушках, без базы
make db                                                  # база на 127.0.0.1:55432, адрес — DATABASE_URL в .env
uv run --env-file .env python -m pipeline.init           # миграции и пакеты в эту базу
uv run --env-file .env uvicorn app.main:app --port 8080  # API на этой базе
uv run python -m pipeline.build_v9_packs --city kazan    # пересобрать автоматический город из v9
make test && make lint
make test-db                                             # + тесты на настоящем PostGIS (база oznayu_test)
```

Версии зафиксированы в `uv.lock`. После правки `pyproject.toml` — `uv lock` и закоммитить lock-файл. CI проверяет это сам.

**CI** (`.github/workflows/ci.yml`) на каждый PR и в `main`:
- `uv lock --check`, ruff и pytest;
- `docker compose up --build` ровно как у жюри, с замером времени до `/health`;
- проверка `/` и `/api/cities`, повторный запуск `init`.

Контракты (факт, плагин, запрос, API, пакет города) — `docs/design/contracts.md`.
